# 앱 고치기

## 설명
- **한 줄 정의**: 대표가 화면 글자로 "이 칸 바꿔 · 추가해 · 이상해"라고 할 때 — F(바꾸라 함)는 그 칸만 고치고, D(이상해)는 원인부터 보고한다.
- **언제 여나**: 대표 "이 칸 바꿔" · "이거 추가해 줘" · "라벨 바꿔"(F), "이 숫자 이상해" · "화면이 깨졌어"(D). 대표는 **화면 글자로** 부른다 — `Today's Take` · `Holdings` · `History Calendar` · `Account : Index` · `Quiet Hands` … 부르는 말: 이 칸 바꿔, 추가해 줘, 라벨, 화면 깨짐, 숫자 이상해, 앱 고치기.
- **두 갈래**: **F 고치기 · 추가** — 대표가 바꾸라고 했다. 스펙을 되읽고 동의를 받은 뒤 고친다(아래 버튼 칸). **D 진단** — 고치기 전에 원인부터 보고하고, 고칠지는 대표가 정한다(아래 판단 칸).
- **가르는 법**: "지금 숫자 얼마야?" → 지금 숫자(화면이 대표 숫자와 다르면 그 일의 의심 순서부터, 원인이 코드면 이 일로). "X 넣어 줘"(장부 한 줄 — CFG 태그 · VIP 기준가 · 입금 · 감시) → 세션 장부 — 앱 코드를 안 건드린다. "관심종목 바꿔" → 관심종목 바꾸기.
  - **"이상해"와 "추가해"가 한 말에 섞이면** → D 먼저(원인부터 — 고칠 칸이 바뀔 수 있다). 물을 때 "기대한 숫자가 뭐였어?"를 같이 묻는다.
- **무엇을 주나**: F — 대표가 바꾸라고 한 칸만 바꾼 코드 → 테스트 → 커밋 → 보고. D — 원인 보고. 보고엔 무엇을 고쳤나 · 테스트 결과(숫자) · 커밋 id · 배포 지연 가능성.

## 물을 것 (D 진단 · F 문 앞 공통)
> 순서가 아니다 — 어디부터 볼지는 그때 판단(원-2026-10-27-12). 화살표 대신 물음.
- 대표가 부른 화면 글자가 어느 패널인가?(영문 그대로 도시를 찾고 — `find_city`, 0건이면 데이터센터 앱 기능에서 고른다) "달력"만이면 휴장일 달력과 갈린다 — 무엇을 보는 화면인지 묻는다.
- 그 패널이 무엇을 보여 주나 · 왜 만들었나?
- 어느 파일 · 함수에서 만드나 · 두 레포 짝 함수인가?
- 캐시 · 스키마 · 종목코드를 건드리나 — 거래로 못 만드는 값은 영구 캐시로 따로 두었나?
- 고치면 무엇이 터지나?(⚠빈줄 · ⚠폭0 — 렌더링 함정 · ⚠dtype — 새로고침과 캐시 · 꺼내는 창구)
- 바꾸는 게 숫자(문턱 · 색 경계 — 값의 집은 세팅)인가, 정의(분모 · 단위 — 그 잣대 사무실)인가?

## D 진단 — 판단 칸
> 숫자 · 화면이 대표 것과 다를 때. 어디부터 볼지는 그때 판단 — 정의 의심이 가장 잦았다.
- **화면이 옛 코드인가**(먼저) — push 뒤라면 배포가 늦을 수 있다(하루까지). `Updated app!` + 트레이스백 없음이면 기다리고, 트레이스백인데 로컬 재현이 안 되면 대표에게 Reboot app — 에러가 애매하면 **Manage app 로그 화면 캡처부터** 부탁한다(리댁트 안 된 원문이 거기 · 세션은 Cloud 로그인 불가, 데이터센터/앱_운용). 옛 코드를 보고 진단하지 않는다.
- **넓은 말 "색"인가** — Holdings엔 색이 여러 곳이다. 어느 색인지 모르면 한 줄로 묻는다. **"녹색"이 옛 뜻일 수 있다** — 10-20에 물타기 카드 녹색 · 파랑 뜻이 바뀌었다(지금 최초진입가 위 = 파랑). 대표가 "녹색 됐어?"면 "최초진입가 넘은 거면 이제 파랑이야"까지 한 줄. 색 규칙 · 겹침은 보유 카드.
- **카드 색이 이상하면**: 현재 사이클 매수 횟수 · 평단 · 최초진입가 · 카드 현재가가 언제 값인가(⚠시점) · 경계(세팅 "물타기 카드 색"). 정답은 코드(`watering_card_state`).
- **정의가 다른 두 숫자를 견주고 있나**(원-2026-10-22-09)
- **언제 값인가** ⚠시점 — 마지막 새로고침 · 캐시 복원(세션 리셋 뒤 옛 결과) · 휴장일 한 줄 두 날짜(휴장일 · 주말엔 스냅샷을 안 찍어 앞뒤 거래일이 한 줄로 이어 보인다 — 데이터센터/새로고침과_캐시 "휴장일 · 주말엔 스냅샷을 안 찍는다") · 애프터장 · 표시가가 멈췄나 · 스냅샷이 장중값인가 · 히스토리가 뒤처졌나(`[정합성]`)
- ⚠복제 — 같은 계산이 두 곳이라 한쪽만 고쳐졌나(계좌_벤치_계산 "⚠복제 wk 여섯 벌" · 세팅 Fishing 줄)
- ⚠기준일 · 기간 — 같은 뿌리인데 화면마다 다르면(Foreigner 주가 칸 09-17). Quiet Hands 외인 변화가 빈칸이면 기준일 뒤에 그 종목 외인 자료가 없다는 뜻(Encore — 오늘 판 종목).
- ⚠조용한0 — 시세 실패 종목이 섞였나.
- WATERING 그래프 선이 늦게 시작하거나 두 점 직선이면 → 그 종목 시세가 언제부터 있나(인프라 크론 백필). 화면 버그가 아니라 백필 범위일 수 있다.
- 그래도 모르면 MD가 아니라 코드를 믿는다.
- 진단이 끝나면 원인 보고 → 고칠지는 대표. 고치라 하면 아래 F 버튼 칸.

## F 고치기 — 버튼 칸
> 이 칸은 버튼이다 — 순서대로. ⛔에서 멈춘다.
- **지킴(걸음 내내)**
  - 라벨 · 색: 영어 첫 글자 대문자 · 상승 빨강 / 하락 파랑 · 모바일 390px · **앱 화면엔 설명 글을 붙이지 않음**(범례는 예외 — 대표 「어차피 난 아니까. 나만 보는거고.」 원-2026-09-04-02 · P&L Actions 버킷 「내가 만든 건데 설명 쓰면 지저분」 원-2026-09-07-02) — 리포트의 그래프 · 표엔 쓰인 용어 설명을 붙인다(대표 「설명글 넣지 않음, 단 리포트에는 그래프나 테이블에 사용되는 용어에 설명글 넣음」 원-2026-10-23-10). **빈 상태 · 조회 시각 안내("새로고침을 눌러…" · "마지막 조회")는 설명 글이 아니다. 이미 있는 설명 캡션(Link · Basecamp · Foreigner 몇 줄)은 대표 말 전엔 그대로 — 새로 붙이지 않을 뿐.** 모바일 폭 390px은 세션이 고른 값(옛 §5 "모바일 웹뷰 기준" — 대표 원문 없음).
    - 대표가 직접 "설명 한 줄 넣어"라고 하면 넣는다 — 되읽기(F1)에서 "앱엔 설명 안 붙이기로 했었는데(원-2026-09-04-02) 넣을까?" 한 번 확인 뒤.

  - **새로고침 둘을 가른다**: 시세 새로고침은 앱을 열 때 세션당 1회 **자동**(그대로). 패널 새로고침(Up/Down · Fishing · Basecamp/Foreigner/Link)은 **자동으로 돌리지 않는다** — 대표가 부하 때문에 일부러 안 넣었고 결과를 ui_cache에 남긴다(원-2026-09-16-04). 새 패널도 이 꼴(버튼 + 캐시).
  - **되돌릴 수 있으면 바로, 못 되돌리면 묻기**(원-2026-10-23-11 ① — 원문 「매번 "이건 물어야 하나" 물어야함」) — 이게 기본이고, **새 섹터를 만들어야 할 때 · 지금 꼴이 아닌 다른 꼴로 DB를 쓸 때(새 표 · 새 칸 · 저장 모양 바꿈)는 따지지 않고 대표에게 묻는다**(고정 예외 — 원-2026-11-04-24를 원-2026-11-04-38이 바로잡음 「내가 말한건 새 섹터 지정. … 이 포맷이 아닌 다른 포맷의 DB를 쓰거나 해야할 때 묻는다는 거지.」). 기존 섹터에 넣는 지정은 하고 보고, 매일 쌓는 DB 쓰기는 묻지 않고 잘 쌓였는지 보고. 펀드 기준가 · 입금은 대표가 값을 다 주면 그대로, 대략이면 한 줄 확인(원-2026-10-27-11 · 원-2026-11-02-10). sync(두 계좌 맞추기)는 반영한 날마다 묻지 않고(원-2026-10-26-03 · 원-2026-11-02-09).
    - 원문 「매번 "이건 물어야 하나" 물어야함」은 할 때마다 "이건 물어야 하나"를 스스로 따져 본다는 뜻이다 — 그 답이 "못 되돌린다"면 묻는다(대표 「3. 나」 원-2026-11-04-16).
  - **말로 하는 관점 제안은 언제든, 기능을 이름 밖으로 넓히는 코드 제안은 먼저 안 함** — 「틀린 게 아니어도 관점 제안을 해도됌. 갯수 상관없음. 언제든지」(원-2026-10-23-12) · 「…이름도 Today's Alarm이잖니.」(원-2026-09-17-03): 이름이 좁게 정한 기능을 드문 경우로 넓히자는 건 갭이 있다는 것만 한 번 알리고 확장은 보류. 세션 혼자 떠올린 "화면에 설명 한 줄"도 관점이 아니라 기능 쪽이라 꺼내지 않는다(대표가 이미 거절한 종류 — 원-2026-09-04-02). 지킴의 "왜"(약속 다섯)는 데이터센터/앱_기능.
1. 대표 설명이 끝났나 — 스펙을 되읽고 한 줄로 돌려준다.
   - ⛔ **동의 전엔 착수하지 않는다.**
2. 크기를 가른다.

5. 테스트 — 코드를 바꿨으면 늘 `pytest tests/ -q` 전체(몇 초) · 계산을 고쳤으면 `tests/test_portfolio_core.py`에 케이스도 더한다. 뒤에 `git status`로 데이터 파일이 안 바뀌었나 본다. AppTest는 CSS · 픽셀을 못 본다 → 픽셀 · 배치는 **Playwright 390px**로 실제로 본다(눈대중 금지). 로컬 `streamlit run app.py`엔 `.streamlit/secrets.toml`이 있어야 한다(빈 파일이어도 로그인 게이트는 지남 — 단 Supabase 패널은 `[supabase]`가 있어야 돈다, 진단 땐 "시크릿 없음 → 패널 비어 보임"과 가른다. 값은 출력에 찍지 않는다).
6. 계산을 바꿨으면 **같은 순간 옛 코드와 나란히** 돌려 차이를 bp로 — 옛 코드는 `git show HEAD:파일`로 꺼내 import, 커밋 메시지에 "최대 차이 N bp".
7. 사무실을 같이 고쳤으면 `python brain_log.py links` · `heads`(`@뇌` 이름표를 옮겼으면 links가 잡는다). 패널 사무실 문장과 코드가 다르면 코드를 믿고 그 사무실 문장을 같은 커밋에서 고친다(원-2026-10-29-11).
8. `git status` — 데이터 파일이 안 바뀌었나. `git add`는 파일 이름을 정확히. 커밋 메시지 끝에 `셀: 사무실명` 또는 `셀: 없음(→ 위크 대조표)`.
9. push → 배포: `Updated app!` + 트레이스백 없음이면 기다린다(하루까지). 트레이스백인데 로컬 재현이 안 되면 대표에게 Reboot app. 빈 커밋으로 재배포를 유도하지 않는다.
10. 보고 — 무엇을 고쳤나 · 테스트 결과(숫자) · 커밋 id · 배포 지연 가능성.
