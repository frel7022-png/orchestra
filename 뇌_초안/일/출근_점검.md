# 출근 점검

## 설명
- **한 줄 정의**: 그날 첫 일 전에 Supabase 세 표(price_history · investor_flow · market_flow)가 직전 거래일까지 다 쌓였나를 재서 대표에게 한두 줄로 보고하는 일. 모자라면 어느 표만 비었나로 원인을 가른다.
- **언제 여나**: 그날 첫 일 전(지침서 2절 "깨면 제일 먼저") · "DB 잘 쌓이고 있어?" · "외인 데이터 괜찮아?" · 숫자가 모자라 보일 때(진단). 매매일지 반영 뒤엔 그 일이 이 일의 점검 층만 빌린다. 부르는 말: DB 점검, 적재 점검, 출근, 잘 쌓이고 있어, DB 빠졌어.
- **두 층**: **점검** — 매일, 아래 버튼 칸, 한두 줄 보고로 끝. **진단** — 숫자가 모자랄 때, 멈춤 칸 "진단", 원인을 가르고 메우기 밖의 DB 쓰기 · 코드 고치기는 제안부터.
- **무엇을 주나**: 대표에게 한두 줄(버튼 5) — 파일은 안 남긴다.

1. `python check_daily_db.py` — 세 표의 최근 날짜별 적재 수(/관심종목 N) · 빠진 종목 · 첫머리 세 줄. 출력 읽는 법은 확인 칸.

   - ⛔ 배당락 · 권리락 다음 날 고친 줄이 조정 기준가 덮어쓰기면 → 고치지 않고 총평에서 짚고, 되돌리기(DB 쓰기)는 대표에게(업그레이드 U-006).
1b. 15:35가 히스토리를 올렸나 — 첫머리 ③ "15:35 실패" 줄.
   - ⛔ 실패 줄이 있으면: **먼저 `git status`로 남의(다른 창) 미커밋 파일이 있나 본다** — 15:35 push는 일부러 pull · rebase를 안 한다(다른 창 작업 트리를 안 건드리려고). 남의 파일이 없을 때만 로컬 커밋이 남았으면 `git pull --rebase` 뒤 push, 없으면 히스토리 다섯(asset · sector · index · bigcap · bench_history)을 이름으로 커밋 · push. 남의 파일이 있으면 멈추고 위크에게.
   - ⛔ 그날 로그에 `[계좌]` · `[지수]` 줄이 없으면(PC 꺼짐 — 15:35가 안 돎): 그날이 **지난 날짜**면 오늘 09:25 FixPrevClose 뒤에 `python daily_close.py 그날` → 히스토리 다섯을 이름으로 커밋(09:25 전에 돌리면 네이버 NXT 값이 박힌다). **오늘 날짜**면 15:35 뒤에만. 매매일지는 다시 넣지 않는다.
   - ⛔ FixPrevClose는 **직전 거래일 하루만** 고친다 — 15:35가 이틀 넘게 안 돌았으면 그 앞날은 KRX 종가 소스가 없다. 그 날들은 메우지 않고 멈추고 대표에게(날짜 · 빠진 파일).
2. 두 계좌 채널 — `both_accounts.csv` 마지막 날(점검 도구가 안 본다 — 따로 한 번). 직전 거래일보다 늦으면 15:35 예약 뒤에 `python sync_both_accounts.py`(두 레포 커밋). 매매일지 반영한 날엔 그 일에서 이미 돎(원-2026-10-26-03 · 원-2026-11-02-09).
3. 빈 날이 있으면 진단 갈래로 휴장인지 누락인지 가르고, 누락이면 바로 메운다(권한) — 장 마감(15:35) 뒤 `python db_fetch_daily_prices.py`(세 표의 오늘 줄도 쓰고 · 15:35 KRX 줄은 안 덮고 · 빈 날을 메운다). 장중이면 메우지 않고 마감 뒤에.
   - 〔도구 사정 — 빈 날은 바로 메운다는 대표 결정(원-2026-10-22-03 · 원-2026-10-23-16)을 마감 뒤로 늦춤: 장중에 빈 날만 메우는 명령이 없어서(위크 · 옛 뇌 검산 ④)〕
   - ⛔ investor_flow 빈 날이 5영업일보다 앞이면 → 못 메운다(API가 최근 5영업일만 줌) — 대표에게.
4. 빠진 매매일지 날 — transactions에서 `메모=일일매매일지` 줄의 마지막 날짜가 직전 거래일보다 앞이면 그 사이 날들을 "○일 · ○일 매매일지 있어?"로 묻는다(빠진 날은 새러데이가 알려 준다 — 원-2026-11-02-07 · 원-2026-11-02-16). 매매가 없던 날엔 매매일지가 없을 수 있으니 "빠졌다"고 단정하지 않는다. asset_history 날짜로는 재지 않는다(15:35가 매일 찍어서 빈 날이 안 보임).
5. 대표에게 한두 줄: 메운 게 있으면 첫 줄에 "어느 날 몇 종목 메웠다" · ⚠ 줄(확인 칸)과 권리락 · 분할 의심은 첫머리 · 세 표의 직전 거래일 적재 수(/N) + 빠진 종목 · 이유 · KRX 종가 로그(직전 거래일 N/N · 안전망이 고친 줄) · both_accounts 마지막 날 · (했으면) sync 커밋 id · (있으면) 빠진 매매일지 날 물음 · 끝에 "오늘 남은 정해진 일: …"(0c).

## 멈춤
- **진단 — 어느 표만 비었나**(판단 자리. 빈 날 · 가짜 행 · 휴장일 달력 경고가 보일 때 — 휴장인지 크론인지는 휴장일 달력 · 정비실 게시판과 맞댄다)
  1. investor_flow만 → 출처 API 개편(09-10 전례) · 5영업일 넘게 비면 못 메운다. 왜 하루도 비면 안 되나: Foreigner · Link · Quiet Hands · CFG가 기준일 대비 외인 보유율 변화를 기간으로 잰다 — 하루가 비면 그 기간 계산이 틀어진다.
  2. market_flow만 → 행이 있나만 본다(값 0은 휴장일 정상).
  3. **셋 다 그날 없음** → 밤 cron이 아직 안 돌았나 · GitHub 스케줄 스킵(08-27). 다음 cron의 빈 날 메우기(최근 5거래일)가 price_history · market_flow를 메우고, investor_flow는 5영업일 안이면 다시 받는다. cron을 정각으로 되돌리지 않는다. 안 돌았나 · 늦나는 자동 일의 실행 이력으로 가른다(설계도실 — 인프라 크론) — 못 보면 "실행 이력 못 봄"이라고 밝히고 다음 cron 뒤 다시 잰다.
  4. 날짜가 하루 밀림 → cron 자정 지연(09-01) · relabel 전에 그 날짜 unique 충돌부터.
  5. 휴장일인데 행이 있음 → 가짜 행(10-05).
  6. 한두 종목만 → 거래정지(관심종목 수 −1) · 방금 편입(investor_flow는 다음 cron 뒤).
- **멈추고 묻는다**: DB 행 **삭제**가 필요해 보인다(가짜 행 등 — 10-05 · 9/24 · 25 전례) · 원인이 코드다(출처 API 교체 등) → 고치지 않고 제안부터(앱 고치기 일).

  - 세 표 재기 · 보고.
  - **빈 날은 바로 메운다**(대표 원-2026-10-22-03 · DB에 관한 건 매번 묻되, 지금처럼 자동으로 빈 날을 바로 메우는 건 솎아내서 묻지 않는다 — 원-2026-10-23-16) — DB 쓰기 중 이것만 예외로 묻지 않는다.
  - 15:35 실패 뒤 히스토리 다섯 커밋 · push · `daily_close.py 그날`(버튼 1b의 때 · ⛔대로) · sync(원-2026-10-26-03).
- **안 함**
  - GitHub Actions "success"만 보고 정상이라 하지 않는다 — 방어 구조라 일부 단계가 실패해도 성공으로 찍힌다.
  - 거래정지 한 종목이나 휴장일을 오류로 보고하지 않는다.
  - 장중에 메우는 명령을 돌리지 않는다 — 오늘 실시간가가 오늘 줄로 남는다. 〔도구 사정 — 빈 날을 바로 메운다는 대표 결정을 마감 뒤로 늦춤: 장중에 빈 날만 메우는 명령이 없어서〕
  - 코드 바로 고치기 · 방어 구조(2 · 3단계 실패가 1단계를 안 깨게) 걷어내기.
- **대표 몫**: 빈 날 메우기 밖의 DB 쓰기(행 지우기 · 고치기 — 못 되돌리니 기본 규칙대로 묻는다, 원-2026-11-04-38) · 행 삭제 승인 · investor_flow 5영업일 밖 빈 날.

## 확인
> 다 쓴 뒤 스스로 맞춰 보는 목록. 출력 줄의 뜻은 여기 한 곳.
- **출력 읽는 법**(`check_daily_db.py`)
  - 휴장일 달력 경고 줄이 있으면 맨 처음 — 휴장일 달력 일.
  - 첫머리 세 줄: ① `[히스토리 다섯 OK]` — 다섯 파일이 같은 날까지 ② `tracking/summary.csv` 오늘 갱신 — 09:30 아침 리포트 맨 앞에서 돈다(09:35 전 · 휴장엔 안 봄) ③ `[15:35 실패 없음(최근 7일)]`. ⚠️ 줄은 보고 첫머리에.
  - ② "⚠️ 픽 추적 … 오늘 09:30 자동 생성에서 안 돎"이 뜨면 → **보고 첫머리에 "09:30 리포트 안 돎" 한 줄.** 다시 만들지는 대표가 정한다(11-02엔 대표가 그날 리포트는 안 써도 된다고 함 — 그날 일, 원-2026-11-02-19의 앞 문장). 조용히 정상으로 넘기지 않는다.
  - 세 표 날짜별 적재 수: **15:35 뒤 · 밤 cron(실제 21~24시) 전엔 price_history만 그날 줄이 있고(15:35 KRX 종가) investor_flow · market_flow는 그날 0** — 정상 꼴(진단 3 "셋 다 없음"과 다르다). 오전 점검이면 어제 줄은 셋 다 있어야 한다.
  - 점검 도구는 행 수만 센다 — 종가가 KRX인지 · 값이 맞는지는 1a 로그로.
- 거래정지 · 휴장을 오류로 말하지 않았나 · "success"만 보고 정상이라 하지 않았나.
- 파일을 안 남겼나(산출물은 보고 한 덩어리).

## 안 맞는 때
- **화면** 숫자가 이상한 일 — 앱 고치기 일의 진단부터, 원천이 비었을 때만 이 일로.
- `both_accounts`와 Supabase `account_snapshot`은 다른 채널이다 — 후자는 앱 새로고침이 쓰고 sync와 무관. 재지 않았으면 말하지 않는다.
- orchestration 칸이 비어 있는 건 meritz 반영 멈춤(10-15, 대표 "meritz는 나중에") — 오류 아님.

## 옛 방법 — 되돌아가지 않게
- 옛 머리 "0a · 0b · 0c는 대표 확인 거리로 그대로 · 나머지는 순서 아님"(위크 1027) — 버튼 일의 버튼 칸은 관용어(원-2026-11-02-13)로 풀렸다. 걸음을 "얻을 것과 찾을 곳(순서 아님)"으로 되돌리지 않는다.
