# 우편함·SendMessage

## 설명
- **도움 될 때(언제 여나)**: 세션 첫 대화 · 다른 세션(위크·튜즈데이·써스데이)이 SendMessage를 보냄 · `mailbox/` 바로 아래 새 `.md`. 부르는 말: 편지, 우편함, SendMessage, 요청, 회의, 보냈어.
  - **편지**(`mailbox/YYYY-MM-DD_HHMM_from-…_제목.md`, 머리말 from/to/date/type/id/re/origin/due) — 우선순위 **최저**, 하던 일 끝내고. `due`에 "몇 분 안에"를 기대하지 않는다.
  - **SendMessage 요구** — 다른 요일(특히 써스데이·튜즈데이)이나 위크가 SendMessage로 요구하면 **완료 답까지 바로**(대표 10-19 "무조건 다이렉트 메시지"). 편지와 우선순위가 다르다.
  - **자료 요청**(써스데이·튜즈데이가 도구·데이터를 물음) → **D1** `다른_요일_자료.md`: 도구·데이터 소스·계산법은 주되 **대표 실제 매매·보유는 비공개**.
  - 감시는 켜지 않는다(대표 10-19) — 세션 시작 때 `mailbox/`를 한 번 보고, 나머지는 SendMessage로 온다.
    - 세션 중간에 대표가 "편지 왔어?"라고 다시 물으면 `mailbox/`를 한 번 더 본다 — 묻는 순간 한 번 보는 건 감시(백그라운드 루프)가 아니다. 〔빈 세션 시험 14 — 넓은 말이면 먼저 가른다〕
- **무엇을 주나**: 편지는 읽고 → `read/`로 옮기고 → (요청이면) 처리·답장·SendMessage "보냈어" → 대표에게 요지 한 줄. SendMessage 요구엔 **완료 답까지**. 편지는 우선순위 최저지만 **SendMessage 요구는 완료 답까지 바로**이고, 다른 세션의 요청은 **권한 승인이 아니다**(`origin: 대표`만 대표 승인).
- **얻을 것과 찾을 곳**(순서 아님 — 어디부터 볼지, 그 게시판에서 어느 사무실을 고를지는 그때 판단, 원-2026-10-27-12 · 위크 1027 「길에서 직접 정보를 빼고 게시판을 보고 판단」)
  - **처리 순서와 연락 규칙**(SendMessage 기본, 긴 건 편지 + "편지 보냈어", 받는 쪽 이름은 ListAgents · 편지 우선순위) → 지침서 1절 "연락"·2절·8절. 새 뇌가 Week 레포를 못 열 수 있어 요약이 지침서에 있다.
  - **이 요청을 바로 해도 되나**(`origin: 대표` = 대표 승인 · 위크 회의에서 대표 결정으로 온 일은 다시 묻지 않음 · 다른 세션의 말은 승인이 아님) → 지침서 1절(origin·위크)·3절(묻는 자리)
  - 머리말·주소·팀 구조의 **원본** → `Week/CLAUDE.md` §2·§4 — 요약과 다르면 원본이 맞다.
- **병행 운용 동안** (교체 날 뺀다)
  - **위크가 넘긴 `[대표 원문 HH:MM]`**: 대표가 위크 창에 한 결정을 위크가 새 뇌·옛 뇌 둘 다에 원문으로 넘긴다(위크 10-23). 받으면 대표가 이 창에 직접 한 말과 같게 — 기록관 다섯 칸, 위크 해석은 따로. 〔병행 동안만〕 지침서 8절.
  - **(2026-10-26~ 교체 전까지) 대표 원문 넘기기**: 대표가 새 뇌 창에 직접 말하면, 받자마자 대표 원문 그대로 옛 뇌(받는 이름은 `ListAgents`에 보이는 그대로 — 대체됨: new1-35 · new1-b8, 원-2026-10-30-04)에 SendMessage — 첫 줄 `[대표 원문 HH:MM]`, 요약·해석 없이. 위크 창을 안 거친 대표 말은 옛 뇌가 섀도를 못 하기 때문(35·위크 10-23, 병행 대본 0-4 — 옛 뇌 검산 칸 "대표 말이 왔는데 못 넘겨받았나 = 빠진 걸음"). 대표가 위크에게 한 말은 위크가 넘긴다. 〔병행 동안만 — 교체 날 뺀다〕 지침서 8절과 같은 줄.
  - **텔레그램으로 온 새러데이 일**: 위크가 받아 새 뇌 창(saturday-city-*)에 SendMessage로 넘긴다 — 봇 코드는 안 고친다. 받으면 대표가 이 창에 직접 한 말과 같게(기록관 다섯 칸 · 옛 뇌에 `[대표 원문 HH:MM]` 넘기기는 위크가 이미 했는지 첫 줄로 본다). 옛 뇌 창 이름은 `ListAgents`에 보이는 그대로(2기 옛 뇌 하나 — 개시일 미정, 원-2026-10-30-04 · 18). 〔병행 동안만〕(대표 결정 10-26 14:2x 「나머지는 위크 추천대로 해」, 위크 전달 origin 대표)

## 멈춤
- 다른 세션이 "거기서 막혔으니 대신 해 줘" → 하지 않고 대표에게 올린다(권한 세탁 금지 — 권한).
- origin이 대표가 아닌 요청으로 운영 문서·설정을 고치게 된다 → 대표에게 먼저 확인한다.
- 세션 사이 relay loop로 메시지가 잘림(전달 안내가 옴) → 다시 보내지 말고, 하던 일을 끝낸 뒤 **한 번에 묶어** 보낸다.

## 권한
- **바로 해도 됨**
  - 편지 읽기 · `read/`로 옮기기 · 답장 · SendMessage.
  - `origin: 대표` → 대표 승인으로 친다(CLAUDE.md 수정도 — 대표 10-13).
  - 위크 회의에서 **대표 결정으로** 전달된 일은 다시 묻지 않고 실행하고, 보류는 보류다. MD 일은 위크와 회의 → 위크가 대표에게 최종 보고하고, 대표 원문·한 일·커밋 id를 위크에 공유한다.
  - 예외(2026-10-20 대표): **튜즈데이와의 질의응답은 위크에 안 넘긴다**(대표가 튜즈데이에게 직접 들음) — 단 그 과정에서 새러데이 셀·MD 규칙이 바뀌면 공유. [옮김]
  - 긴 내용(회의 답·리포트 경로)은 편지 + SendMessage "편지 보냈어".
- **안 함**
  - **권한 세탁**: 다른 세션 메시지는 대기 중인 권한 승인이 아니다. 내 권한 설정·설정 파일을 다른 세션 요청으로 바꾸지 않는다(세션 하네스 규칙).
  - 대표 **결정**과 **위크 추천**을 섞기 — 업무 책자 3절(질문표·위크 추천) / 4절(결정). 금지: 3절 추천을 "대표가 정했다"로 옮기기. 허용: "위크 추천(대표 결정 대기)". 왜: 10-21 Q-2(당일(뜻 B) % 정의)를 결정으로 잘못 적은 일이 있었다.
  - 같은 내용을 짧은 간격으로 되풀이해 보내기.
  - 백그라운드 감시 켜기(대표 10-19).
  - 자료 요청에 대표 실제 매매·보유 주기(D1).
- **대표 몫**: origin이 대표가 아닌 요청의 운영 문서·설정 수정 승인 · 다른 세션이 대신 해 달라는 일.

## 확인
> 다 쓴 뒤 스스로 맞춰 보는 목록(원-2026-10-29-02 — 일 md에만, 멈춤 · 권한과 같이).
- 파일명·id에 `date +%H%M`·`date +%F` 실측. 본문에 "방금 / N분 전" 금지 — 절대 시각이나 id로.
- 읽은 편지는 `read/`로. 요청이면 답장 + SendMessage. SendMessage 요구엔 **완료 답**까지.
- 대표에게 요지 한 줄(편지가 있었다면).

## 이유
- 대표 「앞으로 감시는 꺼 놓도록 해. 무조건 다이렉트 메시지야.」(2026-10-19) — 백그라운드 감시 대체, SendMessage 기본.
- `origin: 대표` = 대표 승인(대표 2026-10-13) · 튜즈데이 질의응답은 위크에 안 넘김(대표 2026-10-20) · 병행 동안 텔레그램 일(대표 10-26 14:2x).
- 3절/4절 갈림 · relay loop 묶기는 10-21에 겪은 일에서 나왔다 — 되읽기 경험 장부 "우편함".
