# 방법론 받기 (B8)

## 설명
- **도움 될 때(언제 여나)**: 대표가 관점·방법·기법을 길게 설명할 때("내 생각엔…", "이렇게 봐야 해", 예시 숫자로 검산하며 정의를 세울 때) · "포프"·"요이땅"처럼 연구 모드를 부를 때. 부르는 말: 방법론, 관점, 내 생각엔, 포프, 요이땅.
  - 설명 → 끝까지 듣기. 검산(대표가 예시로 공식을 세움, 예: Pit Stop 500만 원 예시) → 대표 예시를 그대로 계산해 맞는지 확인해 주는 게 기여. 연구 모드("포프" = 논의 이어감 / "요이땅" = 실제 분석·논문 착수). 연구 모드면 **그 연구의 집**도 같이 연다 — 포프 = 수급 게시판(외인 판단 — 포프·Link·Quiet Hands·CFG 줄기) · 4분면은 기법 게시판. 〔빈 세션 시험 12 G1 말5〕
    - 포프 줄기의 지금 상태: 포프(관찰, 끝) → Link(4분면·감시 — 운용 중) → Quiet Hands(앱 패널, 9/16) → CFG(③ 리포트로 10-02부터 운용, 태그·cfg_track). 대표가 "방법이 있어"라면 이 넷 중 어디에 붙는 말인지부터 듣는다. 〔빈 세션 시험 14 — 넓은 말이면 먼저 가른다〕
  - 가르는 법: "이거 만들어 줘"(스펙) → `앱_고치기.md` — 단 **설명이 끝났는지 되읽고 동의받은 뒤**. 방법론과 스펙이 한 말에 섞여 오면 방법론부터 남기고 스펙은 되물어 확정.
- **무엇을 주나**: 대표가 낸 방법론을 **끝까지 듣고, 원문 그대로 날짜와 함께 남기고, 진짜 반박거리만 대표 주장 범위 안에서 말한** 결과 — 되읽기 동의 · 원문 번호(또는 위크에 원문 전달) · (있으면) 범위 안 반박. 대표가 "전제"로 깐 것은 검증하지 않는다. 지금은 Week 방법론 보관에 두고 셀엔 아직 넣지 않으며(도시 완성 뒤 배치), 구현이 따라오면 안 셋 리포트가 먼저다.
- **얻을 것과 찾을 곳**(순서 아님 — 어디부터 볼지, 그 게시판에서 어느 사무실을 고를지는 그때 판단, 원-2026-10-27-12 · 위크 1027 「길에서 직접 정보를 빼고 게시판을 보고 판단」)
  - **대표 설명에 반론·단서를 붙이려 할 때** — 오해일 수 있다는 전제로 먼저 되읽고, 근거가 있으면 반박한다(원-2026-10-19-17) → 인식의_방 게시판(대표와 생각하는 법) 〔기록관 전수점검 1026〕
  - **원문을 어떻게 남기나**(원문 그대로 번호 · 날짜 · 해석은 따로) → 기록관 게시판
  - **원문과 해석을 가르는 법**(지금은 셀에 넣지 않지만 배치할 때의 규칙) → 뇌관리 게시판(셀 채우기)
  - **비슷한 때 대표가 어떤 이유로 봤나**(반박 전에 이미 대표가 답한 적 있는지) → 바라보는_눈 게시판(판단 사례집)
- **무엇을 내놓나의 꼴 — 태도 다섯** (원본: 옛 쪽지 넷 + §6-28 — 꼬리표)

| 무엇 | 좋은 예 | 나쁜 예 |
|---|---|---|
| 끝까지 듣기 | 설명이 끝난 뒤 "정리하면 A·B·C 맞아?" 되읽기 | 두 문장 듣고 코드 착수(9/08 VIP를 메인 표에 끼워 넣었다 뺌) |
| 진짜 반박만 | 대표 예시 숫자로 계산이 안 맞는 곳을 짚음(Pit Stop 2차 "+70%"는 안 굴린 현금까지 벌점 — 대표가 찾았지만 그런 류) | 근거 없는 동의 · "좋은 생각이에요" |
| 주장 범위 안에서 | 대표가 "저유동성 종목군에서"라 했으면 그 범위로만 | 강한 버전으로 바꿔 반박(허수아비) · 무관한 비교 |
| 전제는 검증 대상 아님 | Link 4분면 "설계 시 깔고 갈 전제" · Basecamp "문턱 대신 순위" — 그 위에서 설계 | "4분면이 맞는지부터 검증해야" · 표본이 작다는 단서 반복 · 극단 폭락 반박 반복 |
| 원문 + 날짜 | `원-2026-10-21-NN` 번호, 대표 말 그대로 | 내 말로 바꿔 적기 · 날짜 없이 "대표 선호" |

- **남기는 곳 (지금 vs 옛 뇌)**
  - **지금**(대표 10-21 "도시 완성 뒤 배치"): 기록관엔 번호만(`쓰는 셀: 없음 — Week 방법론 보관(배치 대기)` — 셀엔 아직 안 넣는다), 원문은 Week 방법론 보관(`*_원문.md`, 위크 창에서 나온 말이면 위크가) → 16:30 방법론 리포트(**그날 대표가 관점·방법론을 냈을 때만 0~1장, 위크가 씀**) → **셀엔 아직 넣지 않음**. 새러데이 창에서 나온 방법론이면 기록관에 번호 + 위크에 원문 그대로 SendMessage(위크가 보관에 합침).
  - **옛 뇌**: claude.md 해당 §에 "대표 원문 + 날짜"로 바로(예: §6-27 Pit Stop 3차 개정 · §6-28 4분면).
  - 〔대기: 배치 시점·담당(위크 업무 책자) — "도시 완성"이 언제인지, 보관 원문을 셀로 옮길 때 새러데이·위크 중 누가 하는지〕

## 멈춤
- 구현이 따라오면 → **구조 결정은 안 셋 리포트로 먼저**(그림·장단점·방향별 추천 → 대표가 고른 뒤 코드).
- 큰 구조변경·되돌리기 어려운 일이면 Plan Mode 제안(`처음_보는_일.md`).
- 원문을 셀에 넣고 싶은 유혹 → 넣지 않는다(지금 규칙). 해석이 원문보다 넓어 보이면 해석은 쓰지 않고 원문만. 10-16 "기간에 따라 뒤집힌다" → 채점 폐지로 넓게 읽은 사고(§6-36 대체됨).

## 권한
- **바로 해도 됨**
  - 대표 예시를 그대로 계산해 맞는지 확인(검산) · 근거가 있으면 범위 안에서 반박(태도 다섯).
- **안 함**
  - 드문 패턴을 대표가 짚었을 때 일반론 반례로 논지를 흐리지 않는다(대표 10-02 「일반론에 비춰서 찾아내고자 하는 것에 논지를 흐리면 안 돼」 · 규칙 확정 원-2026-10-23-10). (옛 "벤치를 유리하게 맞추자는 제안 금지"는 대표 답 G6 버림 — 벤치는 지금 것 그대로, 바꾸는 건 대표 요청 시 원-2026-10-23-15)
  - 설명이 끝나기 전 구현 착수 · 원문을 셀에 넣기(멈춤).
- **대표 몫**: 구조 결정(안 셋 중 고름) · 〔대기: 배치 시점·담당〕.
