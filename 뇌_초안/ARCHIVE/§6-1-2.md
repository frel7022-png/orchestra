## 6-1-2. Streamlit Cloud 재배포 로그가 성공이어도 실제 화면 반영은 늦을 수 있음
- push 후 배포 로그에 `Updated app!`까지 정상적으로 찍혀도, **실제 화면(특히 모바일)에는
  몇 분이 아니라 하루 정도까지 늦게 반영될 수 있음**(여러 번 재발 확인됨, 경위는 `ARCHIVE.md`
  §6-1-2 참고).
- **판단 기준**: 배포 로그에 `Updated app!`가 찍혔고 에러 트레이스백이 없다면 코드는 정상
  배포된 것으로 보고 더 이상 원인을 파고들 필요 없음 — "화면에 아직 안 보인다"는 걸로
  롤백/재배포 시도하며 삽질하지 말고, 시간이 해결해준다는 걸 사용자에게 안내하고 넘어갈 것.
- **에러 트레이스백이 있는 경우(위와 다름 — 이건 실제로 삽질할 가치가 있음): "새 커밋 푸시로
  유도한 재배포"는 이 캐시를 못 지운다, "Reboot app"만 지운다** (2026-09-05 실제로 겪음).
  `portfolio_core.py`에 새 함수(`append_capture_anomalies`)를 추가하고 `app.py`가 그걸
  import하게 고쳐서 커밋·푸시했는데, 배포된 앱이 `ImportError: cannot import name
  'append_capture_anomalies' from 'portfolio_core'`로 계속 죽어있었음 — GitHub엔 그 함수가
  분명히 있었는데도(`git show HEAD:portfolio_core.py`로 직접 확인함) 계속 재현됨. 로컬에서
  똑같은 코드를 그냥 실행 + 완전히 새 가상환경(격리)에서 `requirements.txt`로 처음부터
  설치해서 실행, 둘 다 문제없이 통과 — **코드 버그가 전혀 아니었음**. 확인 삼아 빈 커밋을
  하나 더 푸시해서 "새 커밋에 의한 자동 재배포"를 유도했는데도 **토씨 하나 안 틀리고 같은
  에러가 재현**됨 — 이게 결정적 단서: 일반적인 git push 자동 재배포는 "git pull + 프로세스
  재시작"만 하고 예전 `portfolio_core.py`의 캐시(정확히 뭐가 캐시되는진 불명 — 아마 컴파일된
  바이트코드나 컨테이너 레이어)까지는 안 지움. 사용자가 앱 화면의 "Manage app" → **"Reboot
  app"**(완전 재시작, git pull이 아니라 처음부터 새로 빌드)을 눌렀더니 즉시 해결됨.
  **판단 기준**: "로컬에서 코드/의존성 재현 다 통과하는데 배포판만 에러난다"면 재배포를 더
  기다리거나 빈 커밋을 더 push하며 삽질하지 말고 바로 사용자에게 **Reboot app**을 요청할 것
  (나만으로는 이 버튼을 못 누름 — Streamlit Cloud 로그인이 필요하고 세션이 로그인하는 건
  금지된 동작이라 사용자에게 부탁해야 함). "Manage app" 로그 화면에는 리댁트 안 된 진짜
  에러 원문도 나오니, 에러가 애매하면 그 화면 캡처부터 요청할 것.
