## 업무의 얼굴
- 알아보는 말: "넣었어"·"반영해"·"올렸어"·"매매일지". 파일은 `todaytrans/`에 대표가 넣는다 — 나는 폴더를 감시하지 않으니 말이 있어야 시작한다.
- 가르는 법:
  - 숫자를 **만드는** 일이면 이 길, **말하는** 일("지금 어때?")이면 `지금_숫자.md`.
  - "이자 들어왔어"·배당 입금이면 CSV가 아니라 입금 행 한 줄 — 세션 장부 C5(`../데이터센터/세션_장부.md`).
  - 오늘 첫 대화면 우편함 → 출근 점검이 먼저(지침서 2절).

## 먼저 볼 곳과 왜
1. `../일과/매매일지_반영.md` — **이 일이 뭔지, 무엇을 하면 안 되나**에 답한다. 저장고·금지·자주 틀린 곳이 거기 있다(걸음은 2026-10-22부터 이 길 "걸음"). 입구 `python ingest_daily.py todaytrans/파일 YYYY-MM-DD`. ⚠시점 ⚠dtype — 숫자가 이상하면 holdings를 고치지 말고 transactions를 본다(줄기 §2-5).
2. `출근_점검.md`(길, 점검 층만 빌림) — **외인 DB가 빠짐없이 쌓였나**에 답한다(하루만 비어도 외인 기간 계산이 틀어진다). 입구 `python check_daily_db.py`(첫머리 휴장일 달력 경고부터).
3. `../일과/기록_올리기.md` — **무엇을 어떻게 남기나**에 답한다. 데이터 파일만 이름으로 add, sync는 meritz 몰아 넣는 날에만(걸음 6, 원-2026-10-26-02).
- 시각부터 잰다(`date +%H%M`) — 장중 파일인지가 보고 문장과 다시 넣을지를 가른다.
- 평소엔 설계도실을 열지 않는다(코드가 한다). 아래 갈림 "설계도실로 내려갈 때"만.

## 걸음 (2026-10-22 일과/매매일지_반영 절차·멈출 때에서 옮김)
1. 파일 이름(예: `todaytrans/1020.csv`)에서 날짜를 읽는다. 날짜는 ingest의 두 번째 인자다 — 스크립트는 파일 이름을 안 보니 세션이 읽어 넣는다(`ingest_daily.main`). 여러 날·같은 날 다시 옴은 아래 갈림.
2. `python ingest_daily.py todaytrans/파일 YYYY-MM-DD` — 그 날짜의 기존 반영분을 지우고 이 파일로 바꾼 뒤 재계산(체크포인트 경로). "최근 3일"은 **실행한 날부터 달력 3일**이다(`today − timedelta(days=3)`, `@뇌 safety_days_컷오프`) — 그보다 앞 날은 체크포인트로 굳는다(월요일에 돌리면 금요일이 이미 굳을 수 있다). 굳은 날을 다시 넣어도 ingest가 체크포인트를 버리고 전체 재생한다(`@뇌 체크포인트_막이`, 대표 결정 1 2026-10-21).
3. 확인 칸대로 출력을 읽는다. 출력이 깨져 보이면 `check_history_alignment(날짜)`를 따로 부른다. ingest 끝 "실제 메리츠 앱 화면과 대조하세요"(`@뇌 메리츠_화면대조`)가 행 잘림을 잡는 유일한 그물이다 — 파서는 열 < 13·행 < 2만 막는다(`portfolio_core.parse_daily_trade_csv`). 세션은 보유 수 급감만 보고, 최종 대조는 대표가 메리츠 앱 화면으로 한다.
4. 시세·코드 보충은 ingest가 매번 무조건 한다(`refresh_all_prices`, `@뇌 시세_무조건_갱신`) — 세션은 `[경고]` 줄만 읽는다. 새 종목은 **반영 날 바로** watchlist(csv + Supabase)에 들어가고(ingest 끝 백필), 시세·외인은 **그 종목 시작일부터** 채운다 — 섹터는 비슷한 기존 섹터(기타2 금지)(대표 10-22 17:4x 새 종목 등재 원칙, 「이건 튜즈데이도 마찬가지야」). 섹터가 기타2로 잡히면 아래 갈림.
5. 외인 DB 점검 → `출근_점검.md`(점검 층).
6. 데이터 파일만 이름으로 묶어 commit·push → `../일과/기록_올리기.md`. **sync(`sync_both_accounts.py`)는 돌리지 않는다** — meritz 폴더에도 쓰고 meritz 레포 커밋까지 하는 일이라, **meritz 매매일지를 몰아서 넣는 날에 같이** 한다(대표 「메리츠와의 싱크는 나중에 메리츠 몰아서 매매일지 넣을때」 원-2026-10-26-02). 그 전엔 대표가 "sync 돌려"라고 직접 할 때만(그때도 장 마감 뒤). 대체됨(10-26): 장 마감 뒤면 "sync 돌릴까?"를 묻고 응이면 돌림(원-2026-10-23-11) · 대체됨(10-23): 묻지 않고 sync.
7. 대표에게: 날짜별 매수·매도 건수, 보유 수, 예수금, 커밋 id. 장중 파일이면 "장중까지". 끝에 "메리츠 화면 보유 종목 수·예수금이랑 맞는지 한 번 봐 줘" 한 줄 — 맞춰 볼 수 있는 건 대표 화면뿐이라서.
   - **장중에 넣은 날은 16:00 뒤 같은 날짜로 한 번 더 — 마감본이 안 와도 같은 파일로**(위크 결정 2026-10-20). 그래야 asset·sector·index·bigcap 그날 행이 확정 종가로 바뀐다. ingest는 그날 한 행만 쓰므로 다음 날 ingest가 대신 고쳐 주지 않는다. 돌리기 전에 `date +%H%M`이 1600 이상인지 본다(10-22 시연: 15:59에 한 번 먼저 돌아 16:00에 다시 덮음).
8. 반영한 날 CFG 태그 종목(`cfg_tagged.csv`)에 매도가 있으면 아래 갈림 "CFG 매도".
- 예탁금 이용료·배당금: `transactions.csv`에 `구분=입금`, `수량=1`, `단가=금액`, `메모=예탁금이용료`(배당금은 `종목명=종목`, `메모=배당금`) 한 줄 → 재계산(이 행은 매매일지 재반영으로 안 지워진다). 입금 분기는 종목명을 안 본다 — 예수금만 바뀐다(`portfolio_core.apply_transaction`). 장부 칸은 `../데이터센터/세션_장부.md`.

## 갈림·멈춤
- 장중 파일 → 보고에 "장중까지", 16:00 뒤 같은 날짜로 한 번 더(마감본이 안 와도 같은 파일로).
- 여러 날 → 오래된 날부터. 같은 날 여러 장이면 가장 늦은 것만.
- **이미 반영한 날이 다시 오면**(장중본 뒤 갱신본 · 여러 날 묶음에 지난 날이 섞임) → **새 것으로 통째로 교체**한다. 대표가 그날 일지를 준 뒤에도 매매해서 갱신본이 새로 온 것이다(대표 10-22 가-3, 원-2026-10-22-07). ingest가 그 날짜 반영분을 지우고 바꾼다(§1-2 "그날 하루 전체 누적" — append하면 중복). 대표가 "그게 최종본"이라 하면 같은 파일로 16:00 뒤 재반영(걸음 7).
- 지난 날짜(체크포인트로 굳은 날) → 출력에 `[체크포인트] … 전체 재생` 줄이 나오나 본다.
- 새 종목이 기타2로 잡힘 → 기존 섹터로 지정(`python fix_sector.py 종목명 섹터` + Supabase watchlist.sector). 고를 땐 네이버 업종(m.stock.naver.com integration `industryCode`·동종 종목)과 기존 섹터 선례로. 새 섹터는 만들지 않는다(대표 2026-10-21). **고른 섹터를 근거와 같이 한 줄로 묻고, 답을 받은 뒤 지정한다**(섹터 지정은 매번 묻는 다섯 중 하나, 원-2026-10-23-11). 대체됨(10-23): 갈릴 때만 묻기.
- CFG 태그 종목을 **사거나 팔았으면** → `python cfg_track.py`(사이클 카드 다시 만듦 — 매수 날에도, 안 돌리면 `cfg_track/summary.csv`가 낡는다). 매도면 `--sells 날짜`로 그날 줄을 보고 끝에 한 줄(`../수급/외인_매수_복기.md`). 〔실전 시험 2b 인바디 · new1-35 검산 10-22 밤〕
- DB 점검에서 빈 날 → 휴장인지 cron 누락인지 먼저 가른다. `krx_holidays.csv`(휴장일 달력, 2026-10-21 대표 결정 6)에 있으면 휴장이다(`../정비실/휴장일.md`). 없으면 누락이다 — 빈 날 자동 메우기는 다음 cron이 하고, 외인은 5영업일까지만 메워진다(`../일과/출근_점검.md`). 바로 메운다(대표 가-1 ⓐ — `출근_점검.md` 갈림, 장중엔 `fill_recent_gaps`만).
- 예수금이 메리츠 앱과 다름(총매입·총평가는 맞음) → 검산식 **초기자본 − Σ매수 + Σ매도 − Σ매도세 = 예수금**부터 본다. 대개 예탁금 이용료 입금 행이 빠진 것이다 → 대표에게 금액·날짜를 묻고 입금 행 한 줄(C5). 세금(매도세)이 실현손익에 이미 빠져 있다는 건 `../가치척도/성적_매기기.md` "매도 수익률 재는 법".
- 대표가 VIP 기준가도 같이 불러 줌 → 세션 장부 C4(new1·meritz **두 레포**에 같이).
- 같은 날짜를 다시 넣었는데 신규 0건 → ingest가 저장 전에 끝난다(`@뇌 매매0건_종료`) — 그날 옛 반영분이 그대로다. 멈추고 "신규 0건, 옛 반영분 유지"로 보고한다.
- `[⚠️ 정합성] … 뒤처짐` → **멈추지 않는다**. 어느 파일이 어느 날짜에서 멈췄나 보고 파일별로 고친다(`../일과/매매일지_반영.md` "멈출 때" — 검사는 경고만, 고치는 건 세션). 왜 생기나는 `../관측소/주가_변화.md`(lock-step 재발), 백필은 `../설계도실/인프라_크론.md`(backfill_bigcap_history · 일별시세). 고치는 길: 그날 매매일지 재반영(asset·sector·index·bigcap 한꺼번에), `backfill_bigcap_history.py`(빠진 날만, 있는 행은 안 고침), 있는 행은 `fetch_daily_price_history` 확정 종가 → `snapshot_*(on_date=날짜)`로 손으로 — 보정 도구는 따로 없다. `compute_metrics_at_close`는 **지금 보유**로 계산하니 지난 날짜 asset엔 쓰지 않는다. 고치는 법을 모르는 파일일 때만 묻는다. ⚠시점
- **설계도실로 내려갈 때**(출력이 이상할 때만):
  - `[체크포인트]` 줄이 나왔거나 보유 수·평단이 장중본과 이상하게 다름 → `../설계도실/코드_구조.md` §6-14(재생 체크포인트: 최근 3일은 늘 재생, 체크포인트 날짜 이하 재반영이면 전체 재생 — d3fd1cc). holdings를 손대지 않는다.
  - 파싱 실패·종목 수가 크게 모자람 → `../설계도실/데이터_스키마.md` §1-6(cp949 순서·열 위치·서브헤더·30개 잘림 전례).
  - 고친 섹터가 다음 반영에 옛 값으로 돌아감 → `../설계도실/데이터_스키마.md` §6-24 + `../설계도실/코드_구조.md` §1-3(캐시 분리) — checkpoint_holdings까지 같이 고쳤나(`fix_sector.py`가 세 파일 동시).
  - 종목코드가 끝내 안 풀림·앞자리 0 유실 → `../설계도실/코드_구조.md` §1-3 · 인라인 스크립트면 `dtype={"종목코드": str}`. ⚠dtype
- 멈추고 묻는다: 파싱 실패 · 보유 수가 크게 이상 · 종목코드가 끝내 안 풀림 · git 충돌이나 내가 안 바꾼 파일. 그 밖엔 묻지 않고 끝까지 — 단 새 종목 섹터 지정과 두 계좌 맞추기(sync)는 매번 한 줄로 묻는다(원-2026-10-23-11). 새 보유 종목을 watchlist(Supabase)에 넣는 ingest 끝 백필은 대표가 정한 자동 등재(10-22 「반영 날 바로」)라 따로 묻지 않는다 — 빈 날 메우기(원-16)와 같은 자리.
- **파일이 `todaytrans/`에 없다**(대표가 "넣었어"라는데 그 날짜 파일이 없음) → 반영하지 않고 파일 이름·날짜를 묻는다. 옛 파일로 반영하지 않는다. 〔빈 세션 시험 13〕
