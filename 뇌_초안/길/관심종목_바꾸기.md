## 업무의 얼굴
- 알아보는 말: "관심종목 바꿔"·"이 리스트로"·"X 관심종목에 넣어/빼"·"피싱 목록" — 대표가 **목록**을 건드리는 말. 파일은 `temporary/`에 대표가 둔다(설계도실/데이터_스키마 §6-5).
- 가르는 법:
  - 매매일지 반영(A2)이 아니다 — 거기서도 보유 종목이 관심종목에 자동으로 들어가지만(백필), 대표가 목록을 주는 일은 아니다.
  - 세션 장부(C)가 아니다 — 장부는 한 줄 더하는 일이고, 이 일은 목록을 **합친다**(빠지는 종목은 지우지 않고 `관심끝` 날짜 — 56f704e).
  - 앱 고치기(B7)가 아니다 — 화면이 아니라 앱과 cron이 읽는 자료를 바꾼다.
  - Link 감시목록(C2)과 다르다 — 그건 `link_watch_log.csv`.

## 먼저 볼 곳과 왜
1. `../데이터센터/데이터_지도.md` "관심종목 목록은 두 벌" — **어느 쪽을 바꿔야 하나**에 답한다. **csv = Fishing·Bench·picks**(`load_watchlist()` — ui_portfolio_tab 3곳·picks.py) / **Supabase = 나머지 전부**: cron(price_history·investor_flow) · 앱의 Foreigner·Link·Basecamp·Quiet Hands(`load_investor_flow_db`가 Supabase watchlist와 조인) · 아침 리포트(DB 로더). → 두 벌이 갈리면 앱 안에서도 패널마다 종목 수가 갈린다 — 그래서 import가 **Supabase 먼저 쓰고 실패하면 csv도 안 쓴다**(56f704e). 진짜는 Supabase(나-1). ⚠두벌
2. `import_watchlist.py` docstring — **스크립트가 무엇을 하나**에 답한다: 자동완성으로 이름 정정(`portfolio_core.match_stock_name`) → 지금 목록과 **병합**(`portfolio_core.merge_watchlist` — 새로 들어옴 · 빠진 종목 = `관심끝` 오늘 · 끝났던 종목이 다시 오면 관심끝 비움 · **보유 중인데 빠지면 관심 끝 안 붙이고 경고**) → Supabase `watchlist`(ended_on) 먼저, 실패면 `[멈춤]`·csv 안 씀 → 섹터 안 다룸. ⚠병합 — **파일에 없는 종목은 다 관심 끝이 된다**(아래 갈림 맨 앞).
3. `backfill_watchlist_from_holdings.py` — **보유 종목은 어떻게 돌아오나**에 답한다: csv에 없는 보유 종목을 찾아 첫 매수일부터 시세를 채우고 **Supabase와 csv 둘 다**에 넣는다(코드 확인 2026-10-21). 매매일지 반영 끝에 자동으로 돈다. ⚠기준일
4. `../설계도실/인프라_크론.md` §6-16 — **Supabase에 어떻게 쓰나**에 답한다(anon 키 upsert, `on_conflict=user_id,stock_code`). 지우는 도구는 없다.
5. `../설계도실/데이터_스키마.md` §1-6 — **받은 파일을 어떻게 읽나**(cp949 → utf-8-sig, 잘린 파일).
6. `../데이터센터/스크리너.md` — **바뀐 목록이 어디에 보이나**(Fishing·Bench·Basecamp·Foreigner·Link·QH·Up/Down — 관심 끝은 숨김). 〔연결 실측 10-22 밤 73–74〕
- 시각부터 잰다(`date +%H%M`) — 16:13 cron 전이면 오늘부터, 뒤면 내일부터 새 종목이 쌓인다(관심 끝 종목도 cron은 계속 쌓는다). 〔v1 ②〕

## 대표 원문 (2026-10-22 저녁, 위크 전달) — 이 길의 기본값
- **새 종목은 즉시 등재** — csv와 Supabase `watchlist` 둘 다(import 뒤 같은 날).
- **섹터는 기존 섹터 중 비슷한 곳** — 네이버 업종(integration `industryCode`·동종 종목) 참고, **기타2 금지**, 새 섹터 안 만듦 → `fix_sector.py` + Supabase `watchlist.sector`.
- **시작일부터 자료 채우기** — 새 종목은 들어온 날(시작일)부터 시세·외인을 쌓는다(긴 소급 아님 — 메모리 no_long_backfill과 맞음). 갈림 3("과거 시세 채울까")의 답.
- **탈락은 드물다** — 빠질 땐 지우지 않고 트래킹은 계속하되 **[관심 끝] 태그**(나-1, `스펙_관심끝_표시.md`). 갈림 1·2의 답 — 표시 칸이 생기기 전엔 빠질 종목 목록을 대표에게 보이고 멈춘다.

## 갈림·멈춤
- **"X 넣어/빼"처럼 종목 하나만** → import 파일을 **지금 관심 중 목록 + X**(빼면 − X)로 만든다. 이름 하나만 든 파일을 넣으면 나머지가 전부 관심 끝이 된다(병합 규칙). 지금 목록 = `portfolio_core.load_watchlist`(관심 중만). 〔빈 세션 시험 12 G3 말3 — "안 들고 있는 종목을 넣는 입구"〕
- **매칭 실패 0을 먼저 보고, 새 관심 끝이 많으면 import가 멈춘다**(2ee64d7) — 매칭 실패한 이름이 지금 목록 이름과 같으면 줄을 유지한다(요약 "실패유지"). 그래도 새로 관심 끝이 될 종목이 세팅 "관심 끝 멈춤" 문턱(`portfolio_core.watch_end_needs_confirm`) 이상이면 **아무것도 안 쓰고 목록만 찍고 멈춘다** → 대조표를 대표에게 보이고, 승인 뒤 `python import_watchlist.py 파일 --yes`. 실패가 있으면(실패유지라도) 목록을 대표에게. `--add`/`--end` 옵션은 대표 확인 대기. 〔new1-35 옛뇌 검산 → 위크 판단 origin 대표, 10-22 밤〕
- **바꾸기 전 대조표**: 새 목록 vs 지금 csv(`dtype={"종목코드": str}`) vs Supabase 수(`check_daily_db.py` 첫 줄) vs 보유(`core.load_holdings()`) → 들어오는 종목 · 빠지는 종목 · **보유 중인데 새 목록에 없는 종목**.
- **대표에게 먼저 보이고 멈출 것**(대조표에서 걸리면):
  1. 보유 종목이 새 목록에 없다 → import가 관심 끝을 안 붙이고 경고만 한다(보유 중이면 패널에 남음). 그 사실을 한 줄로 알린다. 보유 종목은 매매일지 반영 끝 백필로도 다시 들어온다(`매매일지_반영.md` 확인 칸). 〔연결 실측 122–124〕
  2. 빠지는 종목을 Supabase에서도 지울까? — **답: 안 지운다, [관심 끝] 태그 + 트래킹 계속**(나-1·대표 10-22 저녁 — 위 원문). 옛 대기 Q-17: 지우는 도구가 없고 되돌리기 어렵다(쌓인 시세·외인은 남기고 watchlist 줄만 지울지도 같이).
  3. 새 관심종목 과거 시세를 채울까? — **답: 시작일(들어온 날)부터**(위 대표 원문). 긴 소급은 안 한다(메모리 no_long_backfill). Fishing 누적은 들어온 날 0%에서 시작.
- 매칭 실패·이름 정정 → 목록을 대표에게 보여 준다. 자동완성은 검색어당 10개라 거래량 적은 종목은 정확한 이름도 실패할 수 있다 — 그땐 종목코드를 찾아 csv에 손으로 한 줄(데이터_스키마).
- 새 종목 섹터 → 기타2로 잡힌다 → 기존 섹터로 지정(`fix_sector.py` + Supabase `watchlist.sector`, 새 섹터 안 만듦 — 섹터 고르는 법은 위 "대표 원문" 칸 · 데이터 쪽은 `../데이터센터/데이터_지도.md` "새 종목 — 시작일부터 자료" — 세팅엔 숫자가 없어 줄이 없다).
- **대표에게 미리 알릴 것 한 줄** 〔v1 ③〕: 빠진 종목은 다음 날 순위표에서 **"탈락"**으로 찍힌다 — Basecamp(`basecamp_rank.csv` → ④ 리포트 신규/탈락), ② 외인 명단(`link_sample/roster.csv` 탈락), Fishing 순위 변동. 순위 변동 칸이 한 번 출렁이는 건 목록을 바꾼 탓이지 시장 신호가 아니라고 말해 둔다.
  - (3c가 낸 다른 하나 — "새 종목은 배당 캐시가 비어 첫 Fishing 새로고침이 오래 걸림"은 **옛판**이다: 배당 조회는 이제 **보유 종목만**이다(`app.py` 시세 새로고침 핸들러의 `portfolio_core.refresh_dividend_yields(holdings…)`). Fishing 새로고침은 배당을 부르지 않는다(Fishing 배당 배지는 09-01에 뺐음). 그래서 이 길엔 넣지 않는다. 새 종목을 **사면** 그때 한 번 조회된다.)
- **진실이 어느 쪽인가** — **답: Supabase가 진짜**(나-1). 옛 대기 〔Q-21 — 새러데이 의견: Supabase 원본·csv 사본(cron·외인 기간 계산이 걸린 쪽, 정비실/저장소 방향)〕 — import가 두 벌을 같이 쓰니 끝 조건은 "두 벌 수가 같다".
