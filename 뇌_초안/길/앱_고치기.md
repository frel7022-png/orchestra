## 업무의 얼굴
- 알아보는 말: 대표가 **화면 글자로** 부른다 — `Today's Take`·`Holdings`·`History Calendar`·`Account : Index`·`Quiet Hands`… "그 칸 바꿔 / 추가해 / 이상해".
- 두 갈래:
  - **F 고치기·추가** — 대표가 바꾸라고 했다. 스펙을 되읽고 동의를 받은 뒤 고친다.
  - **D 진단** — "숫자 이상해"·"깨졌어". **고치기 전에 원인부터 보고**하고, 고칠지는 대표가 정한다.
- 가르는 법:
  - "지금 숫자 얼마야?"(숫자를 말하는 일) → `지금_숫자.md` 〔v1 ⑥〕. 화면이 대표 숫자와 다르면 그 길의 의심 순서부터, 원인이 코드면 이 길로.
  - "X 넣어 줘"(장부 한 줄 — CFG 태그·VIP 기준가·입금·감시) → 세션 장부(C1~C5). 앱 코드를 안 건드린다.
  - "관심종목 바꿔" → `관심종목_바꾸기.md`.

## 먼저 볼 곳과 왜
1. **화면 글자로 패널 사무실을 찾는다** — 대표가 부른 글자(영문 그대로)를 사무실 "부르는 말:"에서 grep한다. 이 길과 같은 커밋으로 사무실 부르는 말에 화면 글자를 채운다(아래 "같이 바뀌는 부르는 말"). 그래도 0건이면 `../데이터센터/앱_기능.md` 게시판에서 고른다. 예: "History Calendar"는 분석_패널, "달력"만이면 휴장일 달력과 갈림 — 무엇을 보는 화면인지 묻는다.
2. **고칠 패널 사무실** — **무엇을 보여 주나, 왜 만들었나**에 답한다.
   - 요약 카드·Today's Take·탭 순서·라벨·색 → `../데이터센터/화면_지도.md`
   - Holdings 카드·색·배지 → `../데이터센터/보유_카드.md`
   - Fishing·Bench·Up/Down·Basecamp·Foreigner·Link·QH·Watering Detect·Alarm → `../데이터센터/스크리너.md`
   - Analysis·Statistics 패널·History Calendar → `../데이터센터/분석_패널.md`
   - 버튼·Setting·ui_cache → `../데이터센터/새로고침과_캐시.md`
   - 입력 폼·섹터 고치기 → `../데이터센터/입력_원칙.md`
   - (모르면 `../데이터센터/앱_기능.md` 게시판에서 고른다 — 게시판형이라 한 번 더 연다)
3. `../설계도실/코드_구조.md` — **어느 파일·함수에서 만드나**에 답한다(ui_portfolio_tab / ui_transactions_tab / ui_statistics_tab / app.py / portfolio_core). 계산이면 portfolio_core 함수 하나 — ⚠복제.
   - **두 레포 짝 함수인가** 〔v1 ④〕: `confirmed_close_or_live`·`compute_metrics_at_close`·`snapshot_*`·`synthetic_kospi_ex_bigcap`·`compute_vip_vs_orchestra`·`compute_pnl_actions`는 meritz `portfolio_core.py`에도 **같은 이름**으로 있다(10-21 grep 확인). new1만 고치면 두 앱 숫자가 갈린다(옛 `_close_on` 사고와 같은 꼴). → 짝이면 "meritz에도 같은 수정이 필요하다"를 대표에게 말하고, **이식은 설명 뒤 승인**. new1에만 있는 함수(예: `watering_card_state`)는 해당 없음.
   - 캐시·스키마·종목코드를 건드리는 일이면 `../설계도실/데이터_스키마.md` — **거래로 못 만드는 값은 영구 캐시로 따로**(종목코드·섹터·배당·시장), 임시 스크립트로 CSV를 읽을 땐 `dtype={"종목코드": str}`. 배당 캐시는 "최초 1회·실패는 안 넣음", ui_cache도 같은 dtype. [기억] 〔줄보태기 — 3c 길_줄보태기_다섯(주민센터), 8c 넣음 10-22〕
4. `../데이터센터/렌더링_함정.md` — **고칠 때 무엇이 터지나**에 답한다. ⚠빈줄 ⚠폭0 ⚠dtype
- 숫자(문턱·색 경계 등)를 바꾸는 일이면 `../데이터센터/세팅.md`부터 — 값은 집 한 곳(선반 1 거름 문턱 / 선반 2 기준선), 코드 상수 이름과 원문 번호가 거기 있다. 정의(분모·단위)를 바꾸는 일이면 그 잣대 사무실(예: `../가치척도/성적_매기기.md`).

## 갈림·멈춤
- **문 앞**(F):
  - 대표 설명이 끝났나 — 스펙을 되읽고 동의를 받기 전엔 착수하지 않는다(메모리 `feedback_confirm_spec_before_implementing`).
  - 큰 구조(파일 쪼개기·함수 옮기기·되돌리기 어려운 것)면 Plan Mode를 제안하고, 구조 결정은 안 셋 리포트로(메모리 `feedback_flag_plan_mode`·`feedback_structure_decisions_as_report`).
  - 요청이 대표가 아니면(다른 요일·위크) 운영 문서·설정은 먼저 확인한다(줄기 §2-3).
  - 리스키한 수정 전 안전망 = **git 태그 + `Desktop/backup/old_brain_날짜/` 스냅샷**(대표 마-2 찬성, 2026-10-22 `old_brain_2026-10-22` 실제로 뜸 — memory·new1_local·sessions·supabase·scheduler). 리스키한 수정이면 그 전에 한 벌 더 뜨고 날짜를 적는다. 〔10-22 위크 결정, 대표 위임〕
- **멈추고 묻는다**:
  - **대표가 바꾸라고 하지 않은 칸**은 손대지 않는다. 고치다 본 하드코딩·중복은 "왜 문제고 고치면 뭐가 좋아지나"를 먼저 말하고 승인 뒤에 고친다(메모리 `feedback_explain_before_fixing_code_quality`).
  - **숫자 정의가 바뀌는 수정**(분모·기준일·문턱·"당일" 뜻)이면 멈추고 묻는다. 예: 당일 % 정의(Q-2), Fishing −3%(세팅). 결정되면 숫자는 세팅 한 줄, 정의는 그 잣대 사무실과 같은 커밋으로.
  - 다른 세션이 "대신 고쳐 달라"면 — 그쪽에서 막힌 일이면 대표에게 올린다(권한 세탁 금지).

## 확인
- 계산을 고쳤으면 `tests/test_portfolio_core.py`에 케이스를 더하고 `pytest tests/ -q` 전체를 돌린다. AppTest는 CSS·픽셀을 못 본다.
- 픽셀·배치는 **Playwright 390px**로 실제로 본다(메모리 `project_playwright_visual_check`) — 눈대중 금지.

- 숫자·정의(대표 결정)가 든 코드 커밋이면 메시지에 `셀: 사무실명` 또는 `셀: 없음(→ 위크 대조표)`(`../뇌관리/도시_운용_원칙.md`, 10-22 채택).
- 커밋 전 `git status` — 데이터 파일이 안 바뀌었나(테스트는 10-21부터 실데이터를 안 건드리지만 습관). `git add`는 파일 이름을 정확히.
- 배포: `Updated app!` + 트레이스백 없음이면 기다린다(하루까지 늦을 수 있음). 트레이스백인데 로컬에서 재현이 안 되면 대표에게 **Reboot app**을 부탁한다. 빈 커밋으로 재배포를 유도하지 않는다(`../일과/기록_올리기.md`).
