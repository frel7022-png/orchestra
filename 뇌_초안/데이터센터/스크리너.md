# 스크리너 — 패널이 무엇을 거르나

## 설명
- **무엇을 주나**: 스크리너 패널(Fishing · Bench · Up/Down · Basecamp · Foreigner · Link · Quiet Hands · Watering Detect · Today's Alarm)이 어느 모집단에서 무엇으로 거르고 어떻게 줄 세우나 — 대표가 그 패널을 왜 만들었나. 거른 종목을 어떻게 판단하나는 분석 빌딩, 값을 어떻게 재나는 관측소.
- **도움 될 때**: 패널이 무엇을 거르나(모집단 · 정렬)를 고치거나 설명할 때 · 두 패널(또는 앱과 리포트)의 명단이 다를 때 · 패널을 처음 읽을 때.
- **생김새 — 패널마다 무엇을 거르나**
  - **"관심종목" = 관심 중**(`watchlist.csv` 관심끝 빈칸 · Supabase `watchlist.ended_on` null). 관심 끝은 지우지 않고 날짜만 남기고(**숨김은 로컬 `watchlist.csv` 관심끝을 본다** — Up/Down은 `portfolio_core.ended_watch_names`, Supabase `ended_on`만 바꾸면 안 숨겨짐 · 새로고침 전엔 세션에 남음〔역출제 2차 1026 — 코드 확인, 위크 채점 뒤〕 [새]), Fishing·Bench·Foreigner·Link·Basecamp·Quiet Hands·Up/Down·아침 리포트에서 숨긴다(`portfolio_core.load_watchlist` 기본, DB 자료는 `portfolio_core.drop_ended`). 자료는 cron이 계속 쌓는다(대표 10-22 (가)(나)(다), 56f704e).
  | 패널 | 모집단 | 거르는 문턱 · 정렬 | 코드 |
  |---|---|---|---|
  | Up/Down | 전량 매도한 종목 | 마지막 매도가 대비, 문턱 = 종목 하루 변동폭 σ의 배수(DOWN·UP, 2026-10-20), σ 못 재면 고정 문턱 | `refresh_updown_data`, `updown_hit` |
  | Fishing | 관심종목 | 기준(누적/전일)×방향(DOWN/UP) 라디오, 문턱 넘은 것만, 넘은 정도 순 + 전일 순위 배지 | `refresh_watchlist_prices`, `get_watchlist_prev_day_ranks` |
  | Bench | 한 번도 안 산 관심종목 | 문턱 없음, (매수횟수, 기준·방향 값, 현재가) 순 | Fishing 결과 재사용 |
  | Basecamp | 관심종목 | 점수 순위(문턱 대신), 받는손 외인이면 녹색 | `basecamp.scan` |
  | Foreigner | investor_flow 있는 종목 | 기준(누적=기준일pp / 전일)×방향, 상위 N + 순위 배지, 보유율 옆에 | `compute_foreign_flags`, `rank_flow_flags` |
  | Link(잠금) | 관심종목 | 4분면 칸 우선(다이버전스→진행형), 칸 안 `_mag`, 꺾임 감점 | `compute_link_candidates`, `link_watch_status` |
  | Watering Detect | 물타는 중(현재 사이클 매수 2회 이상) | 마지막 매수가 대비 −1% 이하(세팅), 줄마다 숫자 셋 = 최초진입가 대비 현재가 `pct_first_cur` · 최초진입가 대비 평단 `pct_first_avg` · 마지막 매수가 대비 현재가 `pct_last`, `pct_last` 오름차순 | `compute_watering_rows` |
  | Quiet Hands | Convoy(물타는 중)·Undertow(Fishing 하락)·Encore(Up/Down 하락) — 하락만 | 외인비중 변화 문턱, 없으면 상위 몇 개 | `foreign_pct_change_since`, `fishing_decline_population` |
  | Today's Alarm | 위 셋(Watering·Undertow·Fishing 전일) | 트리거 = 오늘 급락, 표시값 = 마지막 매수가 대비 / 없으면 회색 대체 하나 | `compute_todays_alarm` |
  - 패널 숫자의 정의·함정(기준일·Fishing·Up/Down·Watering 표시값)은 `관측소/스크리너_재는_꼴.md`.
- **생김새 — 문턱 숫자는 세팅에**
  - 패널마다 거르는 숫자(Fishing ±3%·Bench 50/30·Up/Down σ 배수·Watering −1%·Quiet Hands +3%p·Today's Alarm −5/+5/−10·Top Traded |1%p|)의 지금 값·확정일·이력은 `세팅.md` 선반 1. 여긴 무엇을 거르나(모집단·정렬)만.
  - Up/Down 줄 끝 꼬리 "· 1.4σ"는 매도 뒤 등락 ÷ 하루 σ다(√경과일 없음) — 통계적 σ가 아니라 "그 종목 하루 변동폭의 몇 배"라는 뜻. σ = 하루 로그수익률 표본표준편차(ddof=1)×100, 수익률 20개 이상(`daily_sigma_map`).
  - Watering Detect: 물을 타면 마지막 매수가가 새로 잡혀 명단에서 빠진다 — 의도(09-17 "진정됐다" 설계, `compute_watering_rows`).
  - Today's Alarm: 세 규칙의 설계(무엇을 트리거로, 무엇을 표시로, 없으면 회색 하나)는 2026-09-16~17 대표.
  - 대체(Quiet Hands 상위 5, Alarm 회색 하나, Basecamp 순위)는 **코드가 하는 앱 동작**이다. 코드가 안 해 주는 자리에서 아무것도 안 걸리면 → `../바라보는_눈/견주는_법.md` 반문 1.
  - 카드 색: `보유_카드.md`
- **생김새 — 패널을 읽을 때**
  - **Bench 줄**: ±3% 필터 없음(전부 표시) · 순위변동 배지(▲▼/NEW) 없음 · 단가 칸 없음(2026-09-09 대표 지시). [옮김] 옛 claude.md §6-23
  - **Link 패널**: 다이버전스 상위 8 · 진행형 상위 5만 화면에 — 이탈·차익실현은 매수 후보 성격이 아니라 안 띄운다(계산 결과엔 남음). 감시 중인 종목은 이름 옆 ★. 후보를 감시목록에 넣을지는 대표가 눈으로 보고(자동 편입 안 함, 2026-09-11). [옮김] 옛 claude.md §6-28
  - Fishing·Up/Down 등 패널을 읽을 때마다: 사실을 읽은 뒤 → 눈 셋의 질문을 던진다(`../바라보는_눈/_게시판.md` — 이때 시장은? 외인은? 분모·기간을 바꾸면?). 기억에 맡기지 않고 이 셀에 박아 둔다(대표 원-2026-10-20-13). (사실은 `python eye_card.py 종목명` 한 장으로)
- **생김새 — 공유(뿌리가 같은 데이터)**
  - Volume(Basecamp)·Foreigner·Link·Quiet Hands는 **같은 새로고침**(`refresh_flow_data`)과 같은 session_state를 쓴다 — 어느 버튼을 눌러도 같이 갱신.
  - Foreigner·Link·Fishing은 **같은 기준일**(정의 = 종목별 price_history 첫 행). Link의 dF = Foreigner의 기준일pp(같은 함수). 다만 기준일 계산은 세 곳이다 — 앱 Fishing(`get_first_day_prices_db`), Link/Foreigner(`compute_link_candidates`·`compute_foreign_flags`), ① 리포트(`@뇌 fishing_기준가` 자체). 기준일을 바꾸는 날 셋을 같이 고친다.
  - **Link(잠금) 비밀번호는 앱 로그인과 별개다** — 앱 로그인은 `check_password()`가 `st.secrets` `app_password`로, Link 패널은 **코드 상수 `ui_portfolio_tab.LINK_PASSWORD`**로 잠근다(옛 "외인 매수 → 이후 주가(실험)" 패널 게이트 재사용). 한 번 풀면 **그 세션 동안 유지**(`st.session_state["link_unlocked"]`). 값은 여기 적지 않는다 — 공개 레포 코드에 평문으로 있는 것 자체가 짚을 거리(고칠지는 대표, 업그레이드 후보). 옛 출처 `../ARCHIVE/§6-28.md`. 〔역출제 3차 1026 — 코드 확인, 위크 채점 뒤〕 [새]
  - Quiet Hands 외인 기준값: 그 종목 외인 자료가 기준일(매수일·기준일·매도일)보다 **늦게 시작하면 기준일 뒤 첫 관측값**을 기준으로 쓴다(편입이 늦어 cron이 늦게 붙은 경우 — Fishing 최초가와 같은 원칙, `portfolio_core.foreign_pct_change_since`). 그래서 숫자는 "기준일부터"가 아니라 "기준일 뒤 첫 외인 기록부터"일 수 있다 — 말할 땐 시작일을 붙인다. 〔역출제 3차 1026 — 코드 확인, 위크 채점 뒤〕 [새]
  - Quiet Hands 외인 변화가 빈칸 = 기준일 **뒤** 외인 자료가 없음(오늘 판 종목 등, investor_flow는 T−1까지) — 예전처럼 가장 이른 값으로 미끄러져 전 기간 변화를 "그날 이후"처럼 보이지 않는다(`portfolio_core.foreign_pct_change_since` → None, 대표 9-0 ② ⓐ, ef2a5af Q-27).
  - Fishing 종목명 파랑·Quiet Hands Encore도 Up/Down과 같은 `updown_hit`(σ 문턱)를 따른다 — 판정 하나. 옛 주석(`@뇌 quiet_hands_세모집단` "−2%↓")은 낡았다.
  - 아침 리포트 ① Up/Down은 σ 문턱 없이 매도가 대비 순위만 쓴다(기간 한도 없음, `@뇌 updown_후보`) — 앱(σ 배수)과 갈라져 있다. 같은 "Up/Down"이라도 앱 명단과 리포트 명단이 다를 수 있다.
  - "현재가"만 실시간(`live_quotes`) — 기준가·기준일은 실시간으로 안 바뀐다.
- **생김새 — 지키는 것**
  - Fishing "오늘의 순위"(TOP20 부가 기능)는 v2 전환 때 대표 요청으로 뺐다 — 다시 넣지 않는다. [옮김] 옛 메모리 `project_workflow.md` · 옛 claude.md §6-6
  - 패널마다 같은 모집단을 따로 계산하지 않는다 — 함수 하나를 패널과 알람이 같이 쓴다(`compute_watering_rows`·`fishing_decline_population`).
  - Link 후보를 감시목록에 자동으로 넣지 않는다 — 사람이 한 번 거른다. 넣을 땐 세션이 `add_link_watch_entry` + 커밋, 같은 날 picks_log에도(→ `../추천/추천_사례집.md`). 같은 종목을 다시 감시하면 **새 줄**(옛 줄·옛 기준점 보존), 같은 종목·같은 플래그일만 그 줄 교체(대표 10-22 나-2, d8048e7). 대체됨(10-22): 같은 종목코드면 덮어씀.
  - Fishing 최초가를 로컬 파일에 저장하는 방식으로 되돌리지 않는다(DB 최초 관측일).

## 이유
- Bench를 만든 이유: 대표 "내가 계속 지나친 종목이 지금 어떻게 움직이나"(원-2026-09-09-01).
- 관심 끝은 지우지 않고 숨긴다 — 자료는 cron이 계속 쌓는다(대표 10-22 (가)(나)(다)).
- 패널마다 모집단을 따로 계산하면 화면마다 숫자가 달라진다(2026-09-11 Link·Foreigner) — 그래서 함수 하나를 같이 쓴다.

## 안 맞는 때
- 아침 리포트 ① Up/Down은 σ 문턱 없이 매도가 대비 순위만 쓴다 — 앱 명단과 리포트 명단이 다를 수 있다(위 공유).
