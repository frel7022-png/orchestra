# 앱 운용 — 앱 자료가 언제 어떤 순서로 쌓이나

## 설명
- **무엇을 주나**: 앱 자료가 언제 어떤 순서로 갱신되고 쌓이나를 볼 때 어느 장을 열지, 그리고 배포판·로컬이 어긋날 때 진단하는 꼴.
- **도움 될 때**: 새로고침·Setting·캐시·갱신 순서를 고치거나 설명할 때 · 매매일지 반영으로 무엇이 어떤 순서로 쌓이나 볼 때 · 화면 숫자가 언제 본 값인지 따질 때 · 배포판만 에러가 날 때 · "최근 작업이 뭘 깨뜨렸나" 의심될 때.
- **이 사무실에 사는 장**
  | 이런 상황이면 | 이 장이 도움이 될 수 있어 |
  |---|---|
  | Setting · 새로고침 · ui_cache · 휴장일 스냅샷 | `새로고침과_캐시.md` |
  | 화면 숫자가 언제 값인가 | `../인식의_방/앱_숫자는_보는_시점.md` |
  | 예약이 스스로 커밋하는 것(09:30 아침 리포트 · 15:35 히스토리 다섯) | `../일과/아침_리포트.md` · `../일과/기록_올리기.md` |
- **진단할 때 — 생김새**
  - **에러 없이 화면만 늦으면** — `Updated app!` 뒤 반영이 하루까지 늦을 수 있다. 트레이스백이 없으면 롤백 · 재배포로 삽질하지 말고 기다린다. (얼린 원본 §6-1-2)
  - 배포판만 에러가 나고 로컬·새 가상환경 재현이 다 통과하면 대표에게 **Manage app → Reboot app**을 부탁하고, 에러가 애매하면 그 "Manage app" 로그 화면 캡처부터 요청한다(리댁트 안 된 원문이 거기 있음 — 세션은 Streamlit Cloud 로그인 불가). (얼린 원본 §6-1-2)
  - **로컬 `streamlit run app.py`가 통째로 안 뜨면**(`StreamlitSecretNotFoundError`) — `.streamlit/secrets.toml`이 없어서다. 빈 파일이면 로그인 게이트는 지난다(`app.check_password`가 `"app_password" not in st.secrets`로 검사 · CI도 빈 파일을 만듦) — 단 Supabase 패널은 `[supabase]`가 있어야 돈다(acbc8d8). 값은 출력에 찍지 않는다. (얼린 원본 §6-1-1)
  - `Desktop/backup` 스냅샷을 Git Bash에서 robocopy로 갱신할 땐 `MSYS_NO_PATHCONV=1`을 앞에 붙인다 — 안 붙이면 `/E`가 `E:/`로 바뀌어 깨진다(`MSYS_NO_PATHCONV=1 robocopy SRC DST /E /XD .git __pycache__ /XF *.pyc`). 갱신 여부는 대표에게 확인. — 이건 정기 스냅샷(옛 §6-3) 얘기다. 리스키한 수정 전 안전망 `Desktop/backup/old_brain_날짜/` 한 벌 + git 태그는 세션이 한다(대표 마-2 찬성 · 10-22, 일/앱_고치기 F3) — 둘은 다른 것. (옛 뇌 메모리 — 대표 원문 없음)
  - "최근 작업이 뭘 깨뜨렸나" 의심엔 일반론으로 답하지 말고 **`git log -p`로 그 함수의 실제 변경을 감사한 뒤** 답한다 — 무엇이 바뀌었고 안 바뀌었는지 정확히 보이는 게 더 설득력 있고, 진짜 원인(무관한 옛 구멍)이 드러나기도 한다(2026-08-24 `watchlist_prices.csv` — claude.md엔 "커밋되는 영구 데이터"라 적혀 있었는데 한 번도 커밋된 적 없었음). 앱이 직접 쓰는 파일은 `git ls-files`로 실제 커밋 여부부터 본다. (옛 뇌 메모리 — 대표 원문 없음)
