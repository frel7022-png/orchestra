# 앱 기능 — 앱을 고치거나 설명할 때

## 설명
- **무엇을 주나**: 앱 패널·칸마다 대표 의도·계산·쌓이는 것을 볼 때 어느 장을 열지, 그리고 앱을 고칠 때 대표와 지키기로 한 약속.
- **도움 될 때**: 패널·칸이 무엇을 보여 주나 · 대표가 그 패널을 왜 만들었나 · 그 칸이 무엇을 쌓나를 고치거나 설명할 때(달력 날짜 칸까지) · 앱을 고치자는 말이 나왔을 때 · 기능을 넓히자는 생각이 들 때.
- **이 사무실에 사는 장**
  | 이런 상황이면 | 이 장이 도움이 될 수 있어 |
  |---|---|
  | Holdings 카드 · WATERING · 배당 · 카드 색 | `보유_카드.md` |
  | 스크리너가 무엇을 거르나(대표 의도) | `스크리너.md` |
  | Analysis · Statistics 패널이 무엇을 그리나 | `분석_패널.md` |
- **어떻게 보나 — 앱을 고칠 때 지키는 약속**(원천은 이 장 — 걸음은 `../일/앱_고치기.md` F가 이 줄들을 가리킨다)
  - 대표 설명이 끝났어? 되읽어 동의받았어? (스펙 확정 뒤 착수)
  - **큰 변경**이야? — 파일 쪼개기 · 함수 옮기기 · 되돌리기 어려운 것 · 데이터 파일 지우기(원-2026-10-23-44 ①) · 파일을 새로 만들거나 나누는 것 · 계산 정의 · 분석 방법(원-2026-10-23-12 「…파일을 새로 만들거나 나누는 것, 계산 정의, 분석 방법 도 다 큰거야」) → 코드 전에 `report/`에 리포트(왜 · 구조도 · 안 셋 · 추천), 대표가 고른 뒤.
  - 고치다 **우연히** 본 하드코딩·중복·비효율이야? → 몇 문장으로 "뭐가 문제고 고치면 뭐가 좋아지나"를 말하고 승인 뒤(일부러 찾아다니진 않고, 사소한 스타일은 넘긴다).
  - 이름이 좁게 스코프된 기능(예: "Today's Alarm" = 오늘 것만)을 드문 엣지케이스로 넓히자는 거야? → **기능을 이름 밖으로 넓히는 코드 제안은 먼저 하지 않는다** — 갭이 있다는 것만 한 번 알리고 확장은 보류(원-2026-09-17-03). **말로 하는 관점 제안은 다르다** — 언제든, 개수 상관없이(「틀린 게 아니어도 관점 제안을 해도됌. 갯수 상관없음. 언제든지」 원-2026-10-23-12).
  - 계산 로직을 고쳐? → 테스트 케이스를 같이 넣는다(자동 테스트는 이미 있다, `tests/` · `../설계도실/코드_구조.md` §6-11). 테스트 뒤엔 `git status`로 데이터 파일이 안 바뀌었나 본다(스모크는 사본에서 돈다 — c533531, 그래도 확인).
  - 숫자 정의(분모 · 기준일 · 문턱 · "당일" 뜻)가 바뀌는 수정이야? → 멈추고 묻는다(예: 당일 % 정의 그대로 — 원-2026-10-23-07).
  - 두 레포 짝 함수야?(meritz에 같은 이름 함수) → "meritz에도 같은 수정이 필요하다"를 말하고, 이식은 설명 뒤 승인.
  - 칸 추가가 **입력** 칸이야? → 보유 · 거래를 바꾸는 폼은 안 만든다(원-미상-02 — 두 폼) · 다른 입력 칸은 물어서(`../데이터센터/입력_원칙.md`).

## 이유
- 대표 「이런게 겹쳐있거나 그런건 너가 합리적으로 바꾸기 전에 물어봐서 왜 고쳐도 되는지 그럼 어떤 이득이 생기는지 나에게 설명해주면 나도 점점 컴퓨팅에 이해도가 높아지고 좋아질 거 같은데.」(원-2026-08-25-01 — 2차 출처: 옛 메모리) — 대표 학습용.
- 구조 결정은 리포트로 — 대표도 구조를 알아야 지시가 정확해진다(2026-10-01). (옛 뇌 메모리 — 대표 원문 없음)
- 대표 「이건 일이기 때문에. 그렇게 깜빡하는 일은 일년에 한두 번 나올까 말까고, 나온다 한들 크게 영향 없어. 8/4부터 오늘까지 하루도 안 들어온 적이 없고, 하루에 여러 번씩 들어왔다. 이름도 Today's Alarm이잖니.」(원-2026-09-17-03 — 2차 출처: 옛 메모리)
- 큰 변경 · 관점 제안(원-2026-10-23-12) · 데이터 파일 지우기(원-2026-10-23-44 ①) · 입력 폼(원-미상-02) · 숫자 정의(원-2026-10-23-07).
- 옛 "테스트 필요해지면 먼저 알려라"(`feedback_flag_when_tests_needed`)는 테스트가 이미 있어 "같이 넣는다"로 대체됨.

## 적용 예
> 예는 규칙이 아니다.
- **스펙 먼저 (2026-09-08 VIP)**: 메인 패널에 한 줄로 끼웠다가 대표가 "전용 섹션을 원했다" — 설명이 끝나기 전에 손댄 일. (옛 뇌 메모리 — 대표 원문 없음)
- **좁은 이름 (2026-09-17 Today's Alarm)**: 하루 지나면 사라지는 갭을 들어 넓히자고 했다가 대표가 위 이유로 보류.
- **지은 예**: 동네 약국 입구의 "오늘 영업" 판에 일 년에 한두 번 있는 명절 영업까지 넣자는 말이 나왔다. 약사는 판은 그대로 두고 "명절은 따로 확인" 한 줄만 붙였다.

## 안 맞는 때
- 앱이 아니라 리포트·스크립트를 고치는 일엔 이 약속 중 화면 쪽 줄이 맞지 않는다 — 그 일 md를 본다.
- 대표가 먼저 넓히자고 하면 "먼저 제안하지 않는다"는 이 장의 일이 아니다 — 대표 말대로.
