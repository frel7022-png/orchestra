# 새로고침과 캐시 — 앱 자료가 언제 다시 받아지나

## 설명
- **무엇을 주나**: 앱이 언제 네트워크를 불러 자료를 다시 받나(정해진 버튼에서만), 결과가 어디에 남나(로컬 캐시 — 세션이 바뀌어도 보임), 휴장일엔 왜 히스토리 스냅샷을 안 찍나.
- **도움 될 때**: Setting · 시세 새로고침 · 자동 새로고침 · 패널 새로고침 버튼 · ui_cache · 휴장일 스냅샷이 이상할 때 · 앱을 나갔다 오면 패널이 비어 있을 때.
- **생김새 — 버튼과 하는 일**
  - **시세 새로고침**(세션당 1회 자동 + 수동): 보유 시세·배당·시장 캐시·지수/bigcap 스냅샷·캡처 로그·계좌 스냅샷(Supabase).
  - 총자산 · 대형주 스냅샷은 **15:30 전에만** 찍는다(`portfolio_core.snapshot_live_total_and_bigcap`, `@뇌 앱_15시30_스냅샷_막기`) — 그 뒤 현재가는 애프터장 값이고, 오늘 줄의 주인은 15:35 예약이다(원-2026-11-10-14). 화면의 현재가 · 총자산은 받은 시세 그대로라 15:40 뒤엔 애프터장 값이 보인다.
  - **Setting**: 시세 새로고침 + `refresh_updown_data` → `refresh_fishing_data` → `refresh_flow_data`를 차례로(새 조회 없음 — 버튼 넷을 대신 누를 뿐). Quiet Hands·Bench는 버튼이 없다(공유 상태 재사용). 이 순서라 **Up/Down σ는 이전 `fishing_hist`(캐시)로 잰다** — Fishing이 그 다음에 새로 받는다(σ는 긴 창이라 하루 차이 영향 작음). 하루 시작에 한 번 누를 버튼 하나로 시세 · Up/Down · Fishing · Volume · Foreigner(→ Quiet Hands까지) 새로고침을 다 눌러 줄 수 있냐는 대표 물음(원-2026-09-16-08 — 2차 출처: 옛 claude.md §6-33, 괄호는 세션 덧붙임일 수 있음).
  - **패널 버튼**: Up/Down·Fishing·Basecamp/Foreigner/Link — 각 함수 하나를 부른다.
- **생김새 — 캐시**
  - 배당 "N/A"는 파싱 실패가 아니라 **배당수익률 0%**다 — 0.0으로 저장하고 재시도하지 않는다(`portfolio_core.fetch_dividend_yield`). 반대로 페이지 구조가 달라 계속 파싱에 실패하는 종목(예: ESR켄달스퀘어리츠)은 캐시에 안 넣고 새로고침마다 다시 시도한다(의도된 동작) — 지금은 09-14 네이버 개편 뒤 조회가 멈춰 **새 종목 전부가 이 길**이다(업그레이드 U-039). (얼린 원본 §6-15)
  - 배당 조회는 보유 종목만이라(`app.py` 시세 새로고침의 `refresh_dividend_yields(holdings…)`) 새 관심종목이 Fishing 새로고침을 늦추지 않는다.
  - `save_ui_cache_df`/`load_ui_cache_df`(종목코드 dtype=str), `save_ui_cache_json`/`load_ui_cache_json`. 저장 실패는 조용히 넘긴다(앱을 막지 않게).
  - 키: `flow_hist`·`market_hist`·`price_hist_flow`·`live_quotes`·`fishing_prices`·`fishing_hist`·`updown_results`(파일 이름은 `updown`). `holding_foreign_map`은 대상 아님(버튼 없이 자동 조회). 캐시에 남는 종목 표는 **관심 끝을 뺀 표**다(`market_hist` · `live_quotes`는 거르기 대상 아님)(`refresh_*`가 `ended_watch_names` · `drop_ended`로 뺌).
  - `render_portfolio_tab` **맨 앞에서 한 번에** 캐시를 선 로드한다.
- **생김새 — 지키는 것**
  - 버튼 핸들러에 로직을 인라인으로 복제하지 않는다 — 모듈 함수 하나를 버튼과 Setting이 같이 부른다.
  - 부하 때문에 일부러 안 넣은 자동 새로고침을 늘리지 않는다(원-2026-09-16-04) — 캐시로 해결.
  - `ui_cache/`를 git에 올리지 않는다(.gitignore).
- 새로고침 패널 꼴: 버튼 → `refresh_*` 함수 → session_state → `ui_cache` → Setting에도 연결 · 앱을 열 때 세션당 한 번 시세 자동 새로고침은 `@뇌 시세_자동_새로고침`(session_state 키 `auto_refreshed`, 2026-08-28).
- **휴장일 · 주말엔 스냅샷을 안 찍는다**: 휴장일 · 주말 스냅샷은 "0% even일"을 만들어 Account : Index · DC/UC를 흐린다(옛 claude.md §6-9, 2026-10-15 대표 승인 — 대표 글자 없음). 판정은 `market_traded_on`(`app.py` 464) — 2026-10-21부터 휴장일 달력(`is_krx_closed`)을 먼저 보고, 달력에 없는 날만 실시간 체결 시각으로 본다(조회 실패 None이면 그대로 찍는다).

## 이유
- 대표 지적 — 새로고침이 부하를 줄까 봐 일부러 자동 실행을 안 했는데, 그 때문에 앱을 나갔다 들어오면 매번 다시 눌러야 한다(원-2026-09-16-04 — 2차 출처: 옛 claude.md §6-31) — 그래서 버튼 결과를 캐시에 남겨 다음 세션에도 보이게 한다(옛 claude.md §6-31).
