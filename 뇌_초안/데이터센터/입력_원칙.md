# 입력 원칙

## 설명
- **무엇을 주나**: 이 앱의 데이터 입력은 CSV 업로드(매매일지)뿐이다 — 수동 입력 UI를 다시 만들지 않고, 고칠 일은 세션이 CLI 스크립트로 한다.
- **도움 될 때**: 앱에 입력 폼·편집 UI(종목 추가·평단가·섹터·매수/매도 입력)를 넣자는 생각이 들 때. 섹터를 고쳐야 할 때

## 허용되는 것
- CLI 스크립트(세션이 돌림): `fix_sector.py`(섹터 — 캐시·portfolio_data·체크포인트 세 곳 동시), `import_watchlist.py`(관심종목), `ingest_daily.py`(매매일지), `add_link_watch_entry`(감시목록).
- 순수 조회 UI(Fishing 등) — 보유·거래 상태를 바꾸지 않는 것.

## 하지 않는 것 (옛 금지)
- "종목 편집"·"새 거래 기록하기" 같은 수동 입력 폼을 다시 만들지 않는다(대표가 두 번 지우라고 함).
- 섹터를 인라인 스크립트로 직접 CSV에서 고치지 않는다 → `fix_sector.py`(체크포인트 때문에 되돌아감).
  - **meritz엔 체크포인트도 `fix_sector.py`도 없다**(meritz `portfolio_core.py` checkpoint 0건, 매번 전체 재생) — "체크포인트 때문에 되돌아감"은 new1 얘기다. meritz 섹터가 어디서 다시 채워지나는 **meritz `CLAUDE.md`가 최신 출처**라 고치기 전에 거기부터. 〔역출제 3차 1026 — 코드 확인, 위크 채점 뒤〕 [새]
  - 이유 하나 더: `load_holdings`는 섹터가 **빈 칸일 때만** 캐시로 채운다 — 엉뚱한 값이 들어 있으면 저절로 안 고쳐진다. 그래서 캐시·portfolio_data·체크포인트 세 곳을 같이 고치는 `fix_sector.py`가 있다.
