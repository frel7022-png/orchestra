## 꼬리표
종류: 기능
옛 이름: claude.md "세션 시작 시 할 일" 3번, §6-2 "외인 DB도 같이 확인", §6-9 휴장일 스킵·빠진 날 메우기
저장고: Supabase `price_history`·`investor_flow`·`market_flow`
부르는 말: DB 점검, 적재 점검, 출근

## 절차
1. `python check_daily_db.py [일수]` — 테이블 셋의 날짜별 적재 수와 빠진 종목.
2. 읽는다: price_history·investor_flow는 날짜마다 watchlist 수(지금 181 안팎), market_flow는 KOSPI·KOSDAQ 둘.
3. 모자라면 원인을 짚는다: 거래정지(정상), 휴장(정상), 크론이 안 돎, 네이버 응답 형식 변경.
4. 대표에게 한두 줄로 보고(세션 첫 대화, 대표 2026-10-01 지시).

## 멈출 때
- 거래일 하나가 통째로 비었다 → 크론 실행 이력을 보고 `python db_fetch_daily_prices.py`로 메울지 대표에게.
- investor_flow가 5영업일 넘게 비었다 → 그 사이는 못 메운다는 걸 대표에게(출처 한계는 `../관측소/외인_변화.md`).
- 한 테이블만 며칠째 안 쌓인다 → 출처 페이지가 바뀐 것. 코드 수정은 제안부터.

## 끝났다는 확인 / 산출물
- 대표에게: 세 테이블의 직전 거래일 적재 수 + 빠진 종목과 그 이유. 파일은 안 남긴다.

## 금지
- GitHub Actions "success"만 보고 정상이라 하지 않는다 — 방어 구조라 일부 단계가 실패해도 성공으로 찍힌다.
- 거래정지 한 종목(예: 해태제과식품)이나 휴장일을 오류로 보고하지 않는다.
