# 기록 올리기

## 설명
- **무엇을 내놓나(끝까지)**: 앱엔 GitHub 연동이 없어서 데이터를 바꾸면 세션이 직접 commit·push하고, 두 레포에 같이 있어야 하는 파일은 둘 다 올린다. 끝에 커밋 id, git status 깨끗, push 뒤 Actions Tests 성공.
- **언제 시키나**: 데이터 파일을 바꾼 뒤(매매일지·VIP 기준가·예탁금·감시목록). 대표가 VIP 기준가를 알려 줄 때. 앱·배포가 이상할 때(화면에 늦게 뜸·배포판만 에러). 부르는 말: 올려, push, 커밋, VIP 기준가, ImportError, 배포 에러, 배포판만 에러.
- **얻을 것과 찾을 곳**(순서 아님)
  - 순서의 뼈대 — 바꾼 파일만 add → commit → push → (두 레포 파일이면) meritz도.
  - 무엇으로 재나 — `git`, `sync_both_accounts.py`.
- **걸음** (번호는 다른 장이 부르는 이름이라 그대로 — "걸음 5"·"6")
  1. 바꾼 파일만 이름으로 `git add`(데이터 커밋과 코드 커밋을 나눈다). 코드(.py)나 **도시 파일(`뇌_초안/` 안 무엇이든 — 셀·길·HISTORY·기록관 포함)**을 바꾼 커밋이면 그 전에 `python brain_log.py links`(테스트 `test_links_no_broken_paths_in_city`가 이걸 본다 — HISTORY에서 지침서 링크 앞 ../ 를 빠뜨린 것 하나로 CI가 깨진다, 10-26) — "코드 문 문제 0개"가 아니면 깨진 문부터 고친다(이름표를 지웠거나 함수를 옮긴 것, 2026-10-21).
  2. 커밋 메시지 끝에 협업 표시 줄 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, push. 자동 아침 리포트 커밋도 같은 문구를 코드에 박아 두었다(`auto_morning_report.main`) — 모델이 바뀌면 그 줄도 같이 고친다.
     - **push 뒤 테스트 결과를 본다** — push마다 GitHub Actions `Tests`(`.github/workflows/tests.yml`, main push 때 `pytest tests/`)가 돈다. 실패하면 대표에게 메일이 간다. 몇 분 뒤 `curl -s "https://api.github.com/repos/frel7022-png/orchestra/actions/workflows/tests.yml/runs?per_page=3"`(공개 레포라 gh·토큰 없이 됨)로 내 커밋 `head_sha`의 `conclusion`이 `success`인지 본다. `failure`면 로컬에서 `pytest tests/ -q`로 같은 실패를 찾고(뒤에 `git status`로 라이브 파일이 바뀌었나 — 바뀌었으면 `git checkout -- 파일`) 도시·데이터 원인이면 바로 고쳐 push, 코드 원인이면 고칠 안을 대표에게. 실패는 다음 push마다 이어지니(10-26: 13:13 커밋 하나의 끊긴 링크로 15:20~밤 push 전부 실패, 메일 50통 가까이) 그날 처음 push부터 본다. 〔위크 10-26 밤 — 사고 시뮬 L4 실제〕
  3. VIP 기준가: **대표가 숫자를 불러 주면 그대로 넣는다 — 대략값(「1715여」)이면 한 줄 확인, 숫자 없이 "넣어"면 값을 묻는다**(원-2026-10-27-11 — 원-2026-10-23-11 「매번 물어야함」을 좁힘). 그 날짜·값을 **각 레포에서 `core.snapshot_fund_nav_history(nav, on_date)`로** 넣는다(new1·meritz 둘 다) → 두 레포 각각 commit·push. 이 함수는 같은 날짜를 지우고 새로 넣어 정렬한다(`portfolio_core.snapshot_fund_nav_history`, 테스트 있음) — CSV에 손으로 append하면 같은 날 두 줄이 생길 수 있다. 날짜 = 대표가 준 기준가 적용일 그대로(함수가 on_date를 그대로 믿는다).
     - meritz 매매일지가 왔으면 meritz 레포에서 그 레포 `ingest_daily.py`로 넣는다(아래 sync 앞에).
  4. 두 계좌 히스토리: **매매일지 반영한 날마다 묻지 않고**(대표 「그렇다면 매일해」 원-2026-10-26-03 · 장중본이면 16:00 재반영 뒤) 장 마감 뒤 `python sync_both_accounts.py` → 두 레포 `both_accounts.csv` 각각 commit·push. "장 마감(15:30) 뒤"는 코드 설명이 근거다(`sync_both_accounts.__doc__`, 2026-09-10) — 장중에 돌리면 그 시각 값으로 언다.
     - `ledger/`(후보 장부)는 자동 아침 리포트 커밋에서 빠진다 — 자동 커밋은 `morning_report`·`link_sample`만 올리는데(`auto_morning_report.OUTPUTS`) `ledger.daily`는 리포트가 매일 부른다. 그래서 세션이 데이터 커밋 때 같이 올린다(코드가 고쳐지기 전까지).
  5. **대표가 퇴근할 때**("퇴근할게·간다·내일 봐" — 그날 대화가 다 끝난 뒤라 빠지는 게 없다, 대표 원-2026-10-20-25. 말 없이 끝난 날은 다음 날 `출근_점검.md` 0b에서 전날 치를 먼저): HISTORY 그날 파일(`../HISTORY/_목록.md`에서 날짜) — `python brain_log.py history 날짜` 뼈대 + 손으로 흐름 3~5줄·물어본 것·답한 것·남은 것, `_목록.md`에 한 줄. 셀 이력 칸엔 "날짜 · 무엇 → HISTORY 날짜" 한 줄만(서사는 HISTORY — 위크 결정 2026-10-20).
     **HISTORY에 쓰면서 고른다**: 그날 대화 중 중요해 보이는 것(대표의 관점·결정·이유·바로잡은 해석)은 알아서 골라 맞는 셀에 넣는다 — 셀이 없으면 `../뇌관리/셀_채우기.md`. HISTORY는 다 담고 매일 안 읽는 곳, 셀은 골라 담고 매번 읽는 곳(대표 원-2026-10-20-23).
  6. **하루 끝 옛 뇌 점검**: `python brain_log.py oldcheck` — (a) 아침 지문 뒤 옛 뇌에서 바뀐 줄 중 새 뇌 주소가 없는 줄 (b) 열린 `〔새뇌 대기〕` (c) 세팅 ↔ 코드·옛 MD 숫자 다름. (a)는 `--md`로 표 줄을 찍어 `../뇌관리/_새뇌대기.md`에 붙이고, 도시에 넣으면 옛 쪽 표시를 `〔새뇌 반영 커밋id〕`로(옛 claude.md·메모리 표시는 옛 뇌 창 몫). 전수 감사(옛 MD 전부)는 금요일 주간 리포트 때.

## 멈춤 (멈출 때)
- git 충돌, 내가 안 바꾼 파일이 status에 있다 → 무엇인지 보고 대표에게(남의 작업일 수 있다).
- 09:30 자동 리포트와 겹칠 때: 자동 커밋은 `pull --rebase --autostash` 뒤 push하고, 실패하면 "로컬 커밋은 남음" 로그만 남긴다(`auto_morning_report.main`). 그래서 세션이 push 안 한 커밋은 09:30에 같이 나가고, `morning_report/`를 고치는 중이면 그 수정이 쓸려 들어간다 → 09:30 전후엔 커밋을 push까지 끝내 두고 `morning_report/`는 손대지 않는다.
- **push가 rejected(원격에 새 커밋)** → `git fetch` · `git log HEAD..origin/main --oneline`으로 무엇인지 보고 `git pull --rebase`(남의 미커밋 변경이 있으면 `--autostash`). force push·`reset --hard`는 하지 않는다. 〔사고 시뮬 1026 K8 — 옛 뇌 덧붙임 셋, 위크 채점〕 [새]
  - ① **충돌이 생성 데이터**(순위 CSV `fishing_rank`·`basecamp_rank`·`cfg_rank`·`cfg_log` · `both_accounts.csv` · `asset_history`류 히스토리)에서 나면 **손으로 합치지 않는다** — 원격 쪽을 받은 뒤 그 파일을 만드는 스크립트(리포트·`sync_both_accounts.py`·ingest)를 다시 돌린다.
  - ② rebase 뒤 **코드가 바뀌었으면** `pytest tests/ -q`를 돌리고 통과하면 push.
  - ③ **`git add -A`·`git add .` 금지** — `ledger/`·`.claude/settings.local.json` 같은 남의 미커밋 파일이 같이 실린다. 바꾼 파일만 이름으로 add.
- 배포 로그는 정상인데 화면이 늦다 → 기다리라고 안내(하루까지 늦을 수 있다). 로컬은 통과하는데 배포판만 에러 → 대표에게 "Reboot app"을 부탁(세션은 못 누른다).

## 권한
- **안 함 (금지)**
  - 앞으로 앱에 자동 커밋을 넣게 되면 커밋 실패를 **`except: pass`로 조용히 숨기지 않는다** — 실패 이유를 로그로 남기고 대표가 확인할 화면을 둔다(지금은 앱에 GitHub 연동이 없고 세션이 커밋한다). [옮김] 옛 claude.md 104–105 (§1-5)
  - 앱이 직접 쓰는 로컬 CSV는 커밋됐는지 실제로 `git status`로 본다 — 문서 말만 믿지 않는다(메모리 `feedback_check_uncommitted_local_state_files`).
  - `secrets.toml`·`.claude/settings.local.json` 같은 비밀·로컬 설정을 add하지 않는다. 올리지 않는 목록의 정답은 `.gitignore`다(todaytrans·temporary·files·ui_cache·secrets·mailbox·logs·settings.local).
  - 스모크 테스트는 10-21부터 데이터 경로를 tmp 사본으로 돌려 라이브 데이터를 안 바꾼다(c533531). 그래도 테스트 뒤 `git status`로 데이터 파일·**남의 추적 안 된 파일(`??`)**이 섞였나 본다 — 남의 새 파일 테스트가 깨지면 내 커밋 탓이 아니다(`git log`·`??`로 가름, new1-35 전수 목록 다-5). 대체됨(10-21): "test_app_smoke가 portfolio_data 등을 바꾸니 stage하지 말 것".
  - 빈 커밋을 더 push해서 재배포를 유도하지 않는다(캐시는 Reboot app만 지운다).
  - VIP는 한쪽 레포만 넣지 않는다 — 메모리 `project_meritz_sibling`.
  - force push·`reset --hard` · `git add -A`·`git add .`(위 멈춤).
