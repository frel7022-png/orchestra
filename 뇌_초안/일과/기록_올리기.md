# 기록 올리기

## 설명
- **한 줄 정의**: 데이터 · 도시 · 코드를 바꾸면 세션이 직접 commit · push하고, push 뒤 테스트가 초록인지 보는 일 — 앱엔 GitHub 연동이 없어 세션이 안 올리면 재배포 때 사라진다.
- **언제 여나**: 데이터 파일을 바꾼 뒤(매매일지 · VIP 기준가 · 입금 · 감시목록 · 장부) · 도시 장 · 코드를 고친 뒤 · 앱 · 배포가 이상할 때(화면에 늦게 뜸 · 배포판만 에러 · ImportError). 부르는 말: 올려, push, 커밋, VIP 기준가, ImportError, 배포 에러, 배포판만 에러.
- **가르는 법**: 무엇을 넣나(장부 한 줄 · 묻기 꼴)는 세션_장부(C1 ~ C6). 퇴근 걸음(HISTORY · oldcheck)은 `../일/하루_끝.md`.
- **무엇을 주나**: 커밋 id(git 출력에서) · `git status` 깨끗 · **Actions Tests 초록** · 두 레포 파일이면 둘 다.

## 15:35 히스토리 — 스스로 올라간다
- 15:35 예약(`db_fetch_daily_prices.py --krx-close`)이 `daily_close`로 히스토리 다섯(asset · sector · index · bigcap · bench_history)을 찍고 **스스로 commit · push**한다(`daily_close.push_histories` — 다섯만, `git commit -- 파일`, 2026-10-30 위크 편지 B2, 위크 추천을 대표가 모두 받음 — origin 대표 · 기록관 번호 없음). 실패는 `logs/daily_close_fail.log`.
- `push_histories`는 **commit을 먼저 하고 push는 나중**이다(`daily_close.push_histories` — commit 다음 push). 그래서 **push가 실패하면** 다섯은 이미 로컬 커밋돼 `git status`에 "ahead of 'origin/main'"으로 남는다(로그 "push 실패(로컬 커밋은 남음 …)"). **M으로 남는 건** commit 실패(`push_histories` 안) · `close_day` 실패(`db_fetch_daily_prices.py --krx-close`의 `daily_close.close_day()` 예외 처리 — push를 안 부름) · 손 실행(`python daily_close.py 날짜`는 `close_day`만 부르고 push는 안 부름 — `daily_close.py`의 `__main__`, 실패 로그도 없음)이다. 둘 다 출근 점검 1b에서 `logs/daily_close_fail.log` 먼저(손 실행은 로그가 없다).
- **15:35 push는 pull · rebase를 안 한다**(`daily_close.push_histories` — 다른 창의 작업 트리 · 안 올린 커밋을 안 건드리려고). 그래서 ① 15:35 전에 세션이 커밋만 하고 push를 안 했으면 그 커밋도 같이 나가고 ② 원격에 새 커밋이 있으면 15:35 push가 거절돼 다음 날 아침까지 로컬 커밋으로 남는다. → 15:30 전에 내 커밋은 push까지 끝내 두고, Actions 확인(걸음 4)도 내 `head_sha`로 본다.
- 어제 M으로 남은 다섯은 다음 15:35가 같이 실어 올린다 — `push_histories`는 `git commit -- 파일`(`daily_close.push_histories`)이라 그 다섯 파일의 **작업 트리 전체**(어제 남은 변경 + 오늘 줄)를 한 커밋으로 올린다. 그러니 어제 몫을 따로 손으로 커밋할 필요는 없지만, 어제 M의 원인(commit 실패 · close_day 실패 · 손 실행)은 출근 점검에서 먼저 본다.

## 멈춤
- git 충돌 · 내가 안 바꾼 파일이 status에 있다 → 무엇인지 보고 위크에게(남의 작업일 수 있다 — 11-03 셀관리.md는 시티의 `brain_log.py links` 실행(11:11 → fdf4384)이 원인이었다). 15:35 다섯이 M이면 위 칸.
- 09:30 자동 리포트와 겹칠 때: 자동 커밋은 `pull --rebase --autostash` 뒤 push하고, 실패하면 "로컬 커밋은 남음" 로그만(`auto_morning_report.main`) → 09:30 전후엔 커밋을 push까지 끝내 두고 `morning_report/`는 손대지 않는다.
- **push가 rejected**(원격에 새 커밋) → `git fetch` · `git log HEAD..origin/main --oneline`으로 무엇인지 보고 `git pull --rebase`(남의 미커밋 변경이 있으면 `--autostash`). force push · `reset --hard`는 안 한다.
  - ① 충돌이 **생성 데이터**(순위 CSV · `both_accounts.csv` · 히스토리)면 손으로 합치지 않는다 — 원격 쪽을 받은 뒤 그 파일을 만드는 스크립트(리포트 · `sync_both_accounts.py` · ingest · `daily_close.py 날짜`)를 다시 돌린다.
  - ② rebase 뒤 코드가 바뀌었으면 `pytest tests/ -q` 통과 뒤 push.
- 배포 로그는 정상인데 화면이 늦다 → 기다리라고(하루까지). 로컬은 통과하는데 배포판만 에러 → 대표에게 "Reboot app"(세션은 못 누른다).
