## 절차
1. 바꾼 파일만 이름으로 `git add`(데이터 커밋과 코드 커밋을 나눈다).
2. 커밋 메시지 끝에 협업 표시 줄, push.
3. VIP 기준가: 대표가 준 날짜·값을 new1·meritz `fund_nav_history.csv` 둘 다에 한 줄씩 → 두 레포 각각 commit·push.
4. 두 계좌 히스토리: 장 마감 뒤 `python sync_both_accounts.py` → 두 레포 `both_accounts.csv` 각각 commit·push.

## 멈출 때
- git 충돌, 내가 안 바꾼 파일이 status에 있다 → 무엇인지 보고 대표에게(남의 작업일 수 있다).
- 배포 로그는 정상인데 화면이 늦다 → 기다리라고 안내(하루까지 늦을 수 있다). 로컬은 통과하는데 배포판만 에러 → 대표에게 "Reboot app"을 부탁(세션은 못 누른다).

## 끝났다는 확인 / 산출물
- 커밋 id를 대표(또는 위크)에게, `git status`에 남은 게 없음.

## 금지
- `secrets.toml`·`.claude/settings.local.json` 같은 비밀·로컬 설정을 add하지 않는다.
- `test_app_smoke.py`가 바꾼 라이브 데이터(portfolio_data 등)를 섞어 올리지 않는다 — 메모리 `feedback_pytest_mutates_live_data_files`.
- 빈 커밋을 더 push해서 재배포를 유도하지 않는다(캐시는 Reboot app만 지운다).
- VIP는 한쪽 레포만 넣지 않는다 — 메모리 `project_meritz_sibling`.
