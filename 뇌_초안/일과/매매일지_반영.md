# 매매일지 반영

## 설명
- **무엇을 내놓나(끝까지)**: 매매일지는 그날 하루 전체의 누적이라 같은 날짜를 통째로 바꿔 넣고, 반영 → 확인 → 외인 DB 점검 → push를 묻지 않고 끝까지 한다. 끝에 정합성 OK, 커밋 하나, 대표에게 날짜별 매수·매도 건수.
- **언제 시키나**: 대표가 "넣었어"·"올렸어"(todaytrans/에 매매일지 CSV). 지난 날짜 매매일지를 다시 넣을 때(체크포인트 날짜 이하면 ingest가 알아서 전체 재생 — 출력의 `[체크포인트]` 줄 확인). 예탁금 이용료(입금)가 들어왔을 때. 부르는 말: 매매일지, 넣었어, 반영해.
- **얻을 것과 찾을 곳**(순서 아님 — 어디부터 볼지는 그때 판단, 원-2026-10-27-12)
  - 역할 가름(2026-10-27): **일과 = 언제·무엇**(이 일이 무엇을 내놓고, 무엇을 하면 안 되고, 무엇이 자주 틀렸나) · **일 md(옛 이름 길) = 어떻게**(걸음·갈림·멈춤).
  - 이 일의 걸음·멈춤·권한 → `../일/매매일지_반영.md` "설명"·"멈춤"·"권한"(걸음은 설명 칸 안)(2026-10-22 반영 1차 A2로 옮김, 2026-10-29 새 포맷 — 같은 문장을 두 곳에 두지 않는다). 여긴 무엇·금지·자주 틀린 곳만.
  - **무엇으로 재나**
    - `ingest_daily.py 파일 날짜` — 반영·재계산·스냅샷 한 번에.
    - 정합성 검사 `check_history_alignment` = asset·sector·index·bigcap **4파일의 마지막 날짜만** 본다(`portfolio_core.check_history_alignment`) — 중간에 빈 날, 값이 장중값인지는 못 본다. fund_nav는 검사 밖.
    - `fix_sector.py 종목명 섹터` — 섹터 세 파일 + 체크포인트.
    - **증권사 실현손익 칸은 버린다**: 매매일지 CSV엔 수수료·세금까지 뺀 증권사 실현손익(`parse_daily_trade_csv`의 `실현손익_증권사`, 열 위치 `c[12]`)이 있지만, `import_daily_trades()`는 이 값을 버리고 `"실현손익": ""`로 저장한다 — 실현손익은 거래 재생(`apply_transaction`)이 만든다(transactions가 유일한 진실). 이유: 2026-08-18 앱 실현손익이 증권사 "당일실현"보다 몇백 원씩 크게 나왔을 때(그땐 실현손익에 수수료·세금 미반영, 예수금은 정확) 이 칸을 쓰면 맞출 수 있다는 것까지 확인했으나 대표 「몇백 원 차이니 넘어가자」로 보류. 2026-09-08 세금 모델 교체(매도 때 매도금액 × fee_rate를 실현손익에서도 뺌)로 그 오차는 해소됐다. 대표가 증권사 숫자와 정확히 맞추자고 하면 이 칸을 쓰는 게 출발점. [옮김] 옛 ARCHIVE §6-4 52–68행 · 옛 claude.md 509–524(§6-4)
