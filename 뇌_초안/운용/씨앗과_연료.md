# 씨앗과 연료

## 설명
- **무엇을 주나**: 실현손익은 이익이 아니라 다음 기회에 물탈 씨앗이고, 예수금은 저장된 기회다(세션 요약 — 대표 생각을 세션이 정리, 옛 §6-27 "사용자 전략 프레임") 〔구멍: 대표 원문 없음 — 세션 요약〕 — 매입액은 커지는데 예수금이 버티는지로 계좌를 본다.
- **도움 될 때**: 내 계좌가 잘 굴러가나 볼 때. 실현손익(씨앗)과 예수금(연료)을 어떻게 쓸지, 물타기를 더 할지·멈출지, Pit Stop·P&L Actions가 말하는 걸 판단할 때
- **어떻게 보나 — 물어볼 것**
  - **예수금이 매입금액의 25% 기준선 위에 있나?** — 기준선(뜻 A) = 지금 매입금액(Cost Basis) × 25%(대표 2026-10-21 「25% 로 하자. 매입금액 대비.」, 원-2026-10-21-09). 지금 값의 집은 `../데이터센터/세팅.md`. 고정 금액이 아니라 매입액을 따라 움직인다(매입이 커지면 선도 올라감). 아래면 "선 아래야"라고 짚고 의견을 붙인다(리포트 꼴은 원-2026-10-23-44 ② 「Claude's Read · 주간」 범위 그대로 · 대화에서도 의견은 원-2026-10-23-12 「…종합 한 줄은 해석이어도 됌. 오히려 해석 파트 필요함. 내 관점과 비교하기 위해.…」로 된다 — 판정 · 결정은 대표) — 원문은 「25% 로 하자. 매입금액 대비.」뿐이라 "지켜야 할 · 하한"은 쓰지 않는다. 예: 2026-10-20 매입금액 895.7만 → 선 223.9만, 예수금 162.7만(61만 아래). Claude's Read·주간에서 선 아래면 "선 아래야(예수금 N원 · 선 M원)" + 내 의견("나는 ~로 읽어: 근거")까지 — 판정 · 규칙은 대표(원-2026-10-23-44 ② — 위크 물음 "대표가 아직 안 정한 영역에서 의견 범위 — ⓐ 의견('나는 ~로 읽어')은 말해도 됨, 판정·규칙은 대표 / ⓑ 미정 영역은 의견도 묻고 나서"에 대표 「5-1 A / 5-2 A / 5-3 A / 5-4 A / 5-5 A / 5-6 오케이」의 「5-2 A」). 선 아래일 때 어떻게 하자는 규칙은 아직 없다 — 대표 「예수금은 핏 스탑보고 내가 알고 있으면 된다. 예수금이 어떠니 어떻게 하자라는 규칙은 아직 필요없고 나중에 필요시 정한다.」(원-2026-10-22-04).
  - 매입액(Cost Basis)이 커지는 동안 예수금(Orchestra Refill)이 평행하게 버티나? 같이 처지면 배치(물타기)가 씨앗(익절)보다 빠른 것 — 경고(세션 해석 — 옛 §6-27 1713, 핵심 판과 같은 뿌리).
  - 내 예수금이 "같은 돈이 지수를 따라갔다면의 예수금"(Index Refill)보다 많나 적나? Surplus는 차이가 아니라 **비율**이다 — (Orchestra Refill ÷ Index Refill − 1)×100(%), `@뇌 surplus`. 내 종목 선택이 벤치 대비 연료를 몇 % 더(덜) 쌓았나라는 뜻 — 양방향(음수일 수 있다).
  - 자잘한 익절이 매입 확대를 따라잡고 있나(자기보충 엔진)?
  - 물타기가 마이너스를 흡수했나 — 평단 기준 손익률과 "최초 진입가에 다 샀다면" 손익률의 차이(흡수 %p), 시드가 몇 배로 컸나?
  - 한 번 사서 한 번에 끝난 사이클(FA)이 얼마나 되나 — 최초 진입 판단의 정확도(손익 아님 — 뜻 `../데이터센터/분석_패널.md`). 참고선은 대표 「지금 하락장 7% 진행 중이니 50%만 돼도 제 기능 발휘하는 걸로 볼 수 있다.」(원-2026-09-16-02) — 숫자 집 `../데이터센터/세팅.md`, 국면 기록 → `../데이터센터/관측소/바다.md`.

- 옛 §6-27 "사용자 전략 프레임"(실현손익 = 씨앗, 예수금 = 저장된 기회, 매입액↑·예수금 평행 = 스노우볼)은 세션 요약이다 — 세션 글 그대로는 옛 claude.md §6-27·`../ARCHIVE/§6-27.md`. 옛 뇌 확인(2026-11-03): 옛 §6-27 1708 ~ 1713에도 대표 글자는 없고 따옴표는 단어에만 — 〔구멍: 대표 원문 없음 — 세션 요약〕. 이 장에 쓰는 셀로 걸린 대표 원문은 「예수금 쿠션 역할이라고 하면, 1000만원 있을 때, 750만원만 쓴게 쿠션역할 인거고. 이미 1000만원 원금을 2번 이상 돌린거라. 이건 쿠션이라고 볼 수 없어.」(원-2026-10-13-03)

## 무엇으로 재나
- **P&L Actions Watering 상세 정의**(`portfolio_core.compute_pnl_actions`): n_stock · n_extra_buys = Σ(매수횟수−1) · pl_avg_pct = 평단 기준 손익률 · **pl_first_pct = 현재 수량을 전부 최초 매수가에 샀다 치면 나올 손익률**("물타기 안 했으면" 정규화 값) · **absorbed_pp = pl_avg − pl_first**(물타기가 흡수한 %p, 양수 = 좋음) · seed_first = Σ 첫 매수 수량×단가 · seed_now = Σ 평단×현재 수량 · seed_mult = seed_now ÷ seed_first. 화면 3줄: `Watering N종목·물타기 M회` / `총 손익률 X%(최초 진입가 기준 Y%)` / `물타기 흡수율 +Z%p · 시드 A원→B원 (×N)`. **알려진 근사**: pl_first는 "현재 수량을 최초가에"라 물타기 안 했을 때의 실제 수량(첫 매수분)과 다르다 — 흡수 효과를 보는 정규화 지표로만. 종목 하나면 흡수 %p는 수량과 무관하고, 여러 종목을 합칠 때만 가중치가 근사다. [옮김] 옛 claude.md §6-20
- Pit Stop 네 선: `portfolio_core.seed_engine_series`(Cost Basis·Orchestra Refill·Index Refill(옛 컬럼 이름 무연료예수금)·Surplus), 벤치 `blended_benchmark_cum`, `virtual_realized_cum_by_close_date`·`virtual_unrealized_on`
- P&L Actions: `compute_pnl_actions`(FA·MO·MA 버킷, `watering`의 흡수 %p·시드 배수), 사이클 `_all_cycles`·`_cycle_bucket` — 버킷 정의·분모는 데이터센터/분석_패널
  - 흡수 %p는 평단 기준 손익률 − "지금 수량을 전부 첫 매수가에 샀다면"의 손익률이다 — 물타기가 손실을 몇 %p 줄였나(양수 = 좋음). (근사는 위 Watering 상세 정의 끝 한 곳)
  - 시드 배수는 Σ(지금 수량×평단) ÷ Σ(첫 매수 수량×첫 매수가)다 — 물타기로 굴리는 돈이 처음보다 몇 배인가. 부분매도하면 줄어든다.
- FA 비율: `compute_fa_win_rate`
