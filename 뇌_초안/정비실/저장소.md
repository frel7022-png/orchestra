## 반문 질문
- 이 데이터는 저장소의 어느 칸이야? (시세 일봉 / 외인 수급 / 시장 수급 / 관심종목 / 계좌 스냅샷 / 거래 기록 / 히스토리) — 셀엔 칸 이름으로 쓰고, Supabase 테이블 이름은 "지금 주소"로만 붙인다.
- 지금 주소가 바뀌면(Supabase → 다른 서버) 고칠 곳이 몇 군데야? 아래 목록이 그 답이다 — 늘리지 않는다.
- 새 코드에서 DB를 부를 땐 `portfolio_core`의 `*_db` 함수를 쓰고, `rest/v1`을 새로 직접 부르지 않는다.

## 지금 DB를 직접 부르는 곳 (2026-10-21 grep — 고치지 않음, 이전 때 참고)
- `portfolio_core` — 읽기 `portfolio_core.get_first_day_prices_db`·`portfolio_core.get_first_day_dates_db`·`portfolio_core.load_watchlist_history_db`·`portfolio_core.get_stock_price_history_db`·`portfolio_core.load_investor_flow_db`·`portfolio_core.load_market_flow_db`·`portfolio_core.fetch_peer_account_snapshot`, 쓰기 `portfolio_core.write_account_snapshot`. 나머지 스크립트(cfg_track·casebook·sea·daily_link_report·app·ui_portfolio_tab 등)는 이 함수들을 거친다.
- `db_fetch_daily_prices` — cron 적재(쓰기 upsert + 읽기 `db_fetch_daily_prices.rest_get`). 따로 REST를 부른다.
- `check_daily_db` — 점검 읽기(`check_daily_db.fetch_all`). 따로 REST를 부른다.
- `backfill_watchlist_from_holdings` — 관심종목 편입·백필 쓰기. 따로 REST를 부른다.
- 세션 손 작업 — 섹터 PATCH(2026-10-21 기타·기타2 해체), 가짜 행 DELETE(10-05·10-21) 같은 일회성 스크립트. 남기지 않는다.
- 시크릿: `.streamlit/secrets.toml` `[supabase]`(로컬) · GitHub Secrets `SUPABASE_URL`/`SUPABASE_ANON_KEY`(cron). 키를 셀·커밋에 적지 않는다.

## 방향 (이관 전에 알아 둘 것 — 대표 결정 7)
- DB 읽기·쓰기를 한 모듈(가칭 `store`)로 모은다 — 위의 직접 호출 넷(`portfolio_core`·`db_fetch_daily_prices`·`check_daily_db`·`backfill_watchlist_from_holdings`)이 그 모듈 하나를 부르게. 그러면 서버를 바꿀 때 그 모듈만 고친다(대표: "서버 자체를 바꿀 수 있는 경우도 생기고").
- 셀엔 "저장소의 이 칸"으로 적는다. Supabase는 지금 주소로만.
- 실행은 뇌 이관이 끝난 뒤, 대표와 의견을 나눈 다음. 지금은 방향만.
