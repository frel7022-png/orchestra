# 셀 채우기 (셀 채우는 셀)

트리거: 대표가 반례·정정·새 관점·결정을 말했을 때, 저장고 채점이 새로 나왔을 때, 다른 요일 토론에서 내 판단이 바뀌었을 때, 비교평가에서 차이가 나왔을 때 — 그리고 하루 마지막 커밋 전
한 문장: 새길 건 그 턴에 **한 곳(셀의 한 칸)에만 쓰고**, 대표 원문과 내 해석을 가르고, 커밋 메시지 `셀:` 줄 하나로 나머지 기록(이력·주간 보고·일기)을 대신한다.
상태: 시험판(2026-10-19) · 마지막 확인 2026-10-19
이 셀 안 (게시판 → 이 머리 → 필요한 칸만 펼친다):
- 절차 — 들어오는 길 넷(대표 대화 / 저장고 채점 / 다른 요일 / 비교평가)마다: 보고 → 셀 고르기 → 칸 → 원문·해석 가르기 → `셀:` 줄
- 멈출 때 — 한 문장과 어긋남(충돌), 새 셀이 필요함, 숫자를 적고 싶음, 내 해석이 원문보다 넓어짐, 머리가 15줄을 넘음
- 끝났다는 확인 — 대표에게 "어디 넣었다" 한 줄, 그날 커밋에 `셀:` 줄, 머리 15줄 이하
- 금지 — 대표 원문 칸에 내 말 섞기, 같은 원문을 여러 셀에 복사, 셀에 결과 숫자
- 무엇으로 재나 — `brain_log.py` log(`셀:` 줄 = 이력·일기·주간 보고의 원천) · storage(저장고 표) · heads(머리 15줄) · links(코드 문 검사) · where(코드 문 지금 자리)

## 절차

### 공통 다섯 걸음
1. **보고**: 무엇이 들어왔나 한 줄로. 출처(날짜·창·편지 id·파일 행)를 붙인다.
2. **셀 고르기**: 목차의 "언제 펼치나" 문장 → 게시판 → 셀 **머리의 한 문장**에 대어 본다.
   - 같은 방향 → 그 셀. 반대 방향 → **충돌**(멈출 때로).
   - 둘 이상에 걸리면 원리는 가장 일반적인 셀에, 다른 셀엔 가리키는 줄 하나(포인트 01).
   - 못 고르면 `../셀관리.md` 미분류에 한 줄 — 억지로 넣지 않는다.
3. **칸 고르기**: 반례 → 대표 반례·원문 / 결정 → 대기·결정 남(셀이면 한 문장 고칠 후보) / 일어난 일 → 사례 / 틀렸던 것 → 2티어 / 새 질문 → 반문.
4. **해석 전에 `../바라보는_눈/판단_사례집.md` "대표의 가치관"을 훑는다**(대표 원-2026-10-20-17) — 비슷한 때 대표가 어떤 이유로 봤는지. 대표가 바로잡거나 맞다고 하면 그 자리에서 사례 한 줄(이유 포함).
   **원문과 해석 가르기**: 대표 말은 **기록관**(`../기록관/대표_원문.md`)에 날짜 칸 아래 한 항목(`원-날짜-NN`, 쓰는 셀)으로 원문 그대로. 셀의 대표 원문 칸엔 `- 날짜 「요지」 → 기록관 번호` 한 줄만(2026-10-20 이관). 내 이해는 셀에 따로 `(새러데이 해석)` 줄. **원문보다 넓게 읽지 않는다** — 넓어지면 멈춘다(10-16 "날짜로 자르지 않는다"가 이렇게 생겼다).
5. **기록**: 셀 이력 한 줄 + 그날 커밋 메시지에 `셀: <셀 경로> — <넣은 것 한 줄> (출처)`. 셀관리 이력·주간 보고·일기는 이 줄에서 뽑는다(아래 쓰기 비용).

### 들어오는 길마다 다른 점
| 길 | 무엇을 보고 | 주로 가는 칸 | 다른 점 |
|---|---|---|---|
| **대표 대화** | "왜?"·"아니 그게 아니라"·"이건 기억해"·결정·비유 | 대표 반례·원문, 한 문장 후보 | 넣은 직후 대표에게 한 줄로 되읽기("○○ 셀에 '…'로 넣었어") — 받아 적기 오류(5)를 그 자리에서 잡는다 |
| **저장고 채점** | 체크포인트 도래(`picks.py score`), 근거 사라짐(`tracking.py`), 새 폭락일(`stress_days.py`) | 채점(적용 n·반례 n), 사례(판례 가리킴) | 숫자는 안 옮긴다. 같은 방향 반례가 두 번이면 한 문장 재검토 → 충돌로 대표에게. **쌍둥이**: `pick_cases.py similar`로 견준 쌍이 둘 다 단기 체크포인트에 닿았는데 결과가 갈렸으면 → 그 쌍을 가른 눈 사무실(`../바라보는_눈/`) 예시 칸에 한 줄 + 사례 파일 가리킴, 사무실당 최근 3쌍(넘으면 오래된 건 사례 파일에만). 칸은 미리 만들지 않는다 — 재료가 생길 때 생긴다(빈 칸도 매번 읽힌다, 규율 §18-31) |
| **다른 요일 토론** | 위크 회의 편지, 반박 | 2티어·반문 | **내 판단이 바뀐 것만** 넣는다. 상대 원문은 출처와 함께 짧게. 다른 요일 셀은 읽어도 된다 — 역할 차이를 알고 읽고, 내 도시에 적용할 땐 대표와 함께(대표 10-19). 써스데이는 같은 자료로 다른 결과를 내는 **선의의 경쟁·보완 파트너**다(대표 원-2026-10-20-18) — 읽는 목적은 **내가 놓친 점 찾기**이고, 써스데이가 다르게 본 곳은 바라보는 눈의 재료가 된다(내 셀에 들이는 건 대표와 함께). 반대 방향은 하지 않는다: 새러데이·위크가 써스데이에게 "이거 좋으니 적용해 봐"라고 밀지 않는다 — 받아들일지는 써스데이가 스스로 정한다(써스데이는 대표 관점도 판단할 수 있다) |
| **비교평가** | 추천 사례집 `similar`로 견준 결과, 옛 판례와의 차이 | 반문·한계, 사례 | 같은 차이가 두 번 나오면 새 사무실 후보 → 미분류 → 대표 확인 |

## 멈출 때
- **충돌**: 새로 넣을 것이 셀의 한 문장과 어긋난다 → 덮어쓰지 않고 셀에 `충돌:` 줄 + 대표에게 묻는다.
- **새 셀**: 어느 셀에도 안 맞고 사례가 둘이 됐다(또는 대표 원문 하나) → 제안 → 대표 확인 뒤 만든다.
- **숫자**: 문턱·기간·결과를 적고 싶어진다 → 코드 상수나 저장고로. 셀엔 이름만.
- **넓어짐**: 내 해석 줄이 대표 원문보다 더 많은 걸 말하고 있다 → 원문만 남기고 대표에게 확인.
- **머리 초과**: 셀 머리가 15줄을 넘는다 → 사례는 판례(저장고)로, 묶음은 하위 사무실로.

## 끝났다는 확인
- 대표에게 "어디 넣었다" 한 줄(대화 중이면 그 턴, 아니면 주간 리포트 "뇌 변경 보고").
- 그날 커밋에 `셀:` 줄이 있다. 새길 게 없었던 날도 대표와 대화했으면 `셀: 없음` — **훅이 없어도** 하루 마지막 커밋에서 한 번은 스스로 묻게 된다.
- 머리 줄 수: `python brain_log.py heads`가 0으로 끝난다(전부 15 이하). 저장고를 바꿨으면 `python brain_log.py storage`.

## 금지
- **행동을 바꾸는 규칙엔 좋은 예·나쁜 예를 붙인다**(말투·분량·순서처럼 습관에 기대는 규칙) — 좋은 예 = 그대로 따라 할 짧은 답, 나쁜 예 = 실제로 틀렸던 답. 문장 하나만으론 안 바뀐다: 2026-10-20 위크 골든 G23에서 "말은 뒤집힐 때만" 규칙이 있었는데도 해석이 그대로인 종목에 눈 셋을 불릿 열 줄로 다 채웠다(메모리 feedback_rules_need_examples). 길의 금지/허용/왜 꼴이 같은 뿌리다.
- 규칙을 절대 문장("~는 만들지 않는다")으로만 쓰지 않는다 — 무엇을 막으려는지 이유를 붙이고(**왜 그렇게 됐나까지** — 원-2026-10-23-12), 진짜 금지는 사고 난 곳에만(원-2026-10-20-16). **사고 = 숫자 데이터가 틀린 것**. 리포트 분석 중 대표가 지적한 것은 사고가 아니라 **반박 사례** — 금지로 굳히지 말고 대표와 함께 가다듬는다(원-2026-10-23-11). 새 문서를 만들 땐 이미 있는 어느 집과 겹치나 먼저 본다(원-2026-10-23-12). 나쁜 예: "도구가 아니라 눈이다". 좋은 예: "도구가 뽑고 거르면, 눈이 다시 본다 — 기간이 덜 찬 숫자로 확정하는 것만 도구에 맡기지 않는다".
- (지금 단계) 새 빌딩을 지을 때 옛 claude.md 내용을 통째로 옮기지 않는다 — 형식·자리·길(가구)부터, 내용을 두껍게 채우는 건 도시 구조가 굳은 뒤(대표 2026-10-20 "이사한다고 생각하고 가구 먼저", 기록관 원-2026-10-20-07). 시험판 셀에 이미 들어간 원문·사례는 유지.
- 대표 원문 칸에 내 말을 섞지 않는다.
- 코드를 **줄 번호로 가리키지 않는다** — 코드를 고치거나 쪼개면 줄이 밀려 문이 조용히 엉뚱한 줄을 가리킨다(대표 2026-10-21 걱정, 실제로 10-21 `morning_report` 수정 하나로 문 하나가 밀렸다). 함수·상수면 심볼 문, 함수 안 특정 갈래면 이름표 문. 나쁜 예: 파일 이름 + 콜론 + 줄 번호(portfolio_core 3669줄 같은 꼴). 좋은 예: `` `portfolio_core.rebuild_portfolio_incremental` ``, 갈래는 `` `@뇌 safety_days_컷오프` ``(코드 그 자리 위에 `# @뇌 safety_days_컷오프` 한 줄 — 코드엔 셀 경로를 쓰지 않는다, 셀 이름이 바뀌면 썩으니까). 이름표는 아껴 붙인다(같은 자리는 하나로). 지금 자리는 `python brain_log.py where <이름>`. 검사 = `brain_log.py links`·`tests/test_brain_log.py`(HISTORY·ARCHIVE·기록관은 그날 기록이라 검사 밖).
- 같은 대표 원문을 여러 셀에 길게 복사하지 않는다 — 원문의 집은 기록관 하나, 셀은 전부 날짜 + 요지 + 기록관 번호. 여러 셀이 쓰면 기록관 항목의 "쓰는 셀"에 더한다.
- 셀에 결과 숫자를 적지 않는다.
- 셀관리 이력·주간 보고·일기를 셀과 따로 손으로 다시 쓰지 않는다 — `셀:` 줄에서 뽑는다(제안, 위크·대표 확인 전까지는 시험).

## 쓰기 비용 (위크 요청 5)
**지금 규율대로 하면 한 사건을 쓰는 곳**: ① 셀 칸 ② 셀 이력 ③ 셀관리 이력 ④ 원본 사본 덧붙임 ⑤ 하루 일기 ⑥ 판례(사례집 장) ⑦ 주간 리포트 뇌 변경 보고 ⑧ 커밋 메시지 → **최대 8곳**.
**줄이는 안**: 손으로 쓰는 건 ① 셀 칸 + ⑧ 커밋 `셀:` 줄 두 곳(+ 판례가 있는 일이면 ⑥). 나머지는 뽑아낸다.
- ②③ 이력 ← `git log --grep "셀:" -- <셀 경로>`
- ⑤ 일기 ← 그날 `셀:` 줄 + "대표가 짚은 것" 한 문장
- ⑦ 주간 뇌 변경 보고 ← 그 주 `셀:` 줄 모음
- ④ 원본 사본 ← **계속 기록(대표 결정 2026-10-19, 반론 1 들은 뒤)**. 그래서 손으로 쓰는 곳은 셀 칸 + 커밋 `셀:` 줄 + 원본 사본 한 줄 = 세 곳. 비교는 태그 `brain-baseline-2026-10-19` 판으로

**채택(규율 v0.9 §16, 위크 결정 2026-10-19)** → `brain_log.py`(log·storage·heads), 테스트 `tests/test_brain_log.py`. 원본 사본(④)은 대표 결정으로 계속 기록 — 비교군은 git 태그로 분리.
