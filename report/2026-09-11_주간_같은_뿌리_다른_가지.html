같은 뿌리, 다른 가지

이번 주는 커밋 137개(new1 94·meritz 43), 리포트 5건, 그리고 금요일 하루 만에 새 프로젝트(Link) 하나가 통째로 태어난 주였다. 표면적으로는 기능이 잔뜩 늘었지만, 한 꺼풀 벗기면 이번 주 내내 반복된 질문은 하나였다 — "이 두 화면이 같은 숫자를 보고 있는가." index_history가 asset_history보다 뒤처지고, Foreigner와 Link가 서로 다른 외인 기준을 쓰고, new1과 meritz가 같은 날짜를 다른 값으로 기억하는 사고가 네 번째로 재발했다. 그때마다 패치가 아니라 "뿌리를 하나로 합친다"는 같은 해법으로 풀었다 — 그리고 그 해법이 그대로 new1·meritz라는 두 계좌 자체의 이야기이기도 했다: 같은 153종목 뿌리에서 출발했는데, 진입 타이밍 하나로 갈린 두 가지.

03 부침과 해결 — 이번 주 걸린 버그들

전부 "패치"가 아니라 "근본 원인 제거"로 처리한 것들
  1. index_history / bigcap_history 오염 — 이번에 4번째 재발 (월·수 이틀에 걸쳐 두 번 더). 근본 원인: ingest_daily.py가 과거 날짜를 반영할 때도 실시간 시세를 썼음 — 장중에 과거 날짜를 반영하면 그 날짜 행이 "오늘 장중값"으로 덮여버림. 확정 종가(fetch_daily_price_history)를 우선하는 _close_on() 헬퍼로 양쪽 레포 모두 교체하고 오염된 구간을 재생성. new1·meritz 두 레포가 같은 날짜에 다른 숫자를 갖는 사고를 구조적으로 막음.
  2. Holdings 카드 raw HTML 노출 — 같은 버그가 두 번(meritz 화·new1 목). Streamlit 마크다운이 "공백만 있는 줄"을 빈 줄로 취급해 열린 <div> 블록을 끊어버리는 문제 — 조건부로 전부 비는 조각을 단독 줄에 두면 재현됨. 두 번째 재발 뒤 CLAUDE.md §1-8로 원칙화(비는 조각은 항상 확실히 채워지는 태그와 같은 줄에 붙일 것) — 세 번째는 없어야 한다.
  3. VIP 패널 staleness — both_accounts.csv가 세션이 sync를 돌린 "그 순간"에 얼어서, 장중엔 상대 계좌가 실제로 얼마나 움직였는지 못 따라감. 패치 대신 Supabase 런타임 채널을 깔아 양쪽 앱이 새로고침마다 자기 상태를 실시간으로 공유하게 구조를 바꿈 — both_accounts.csv는 "마감 후 확정 히스토리"로 역할이 좁혀짐.
  4. Link 배포 크래시(금) — _render_link_panel 호출부에서 flow_hist/price_hist_flow 인자 순서가 바뀌어 KeyError로 배포판이 죽음. 키워드 인자로 고쳐 같은 실수가 조용히 재발하지 않게 함.
  5. 누락 체결 보정 2건 — meritz 9/1(계룡건설·씨앤씨인터내셔널·오리온), new1 9/10(미스토홀딩스·삼양패키징·크라운해태홀딩스). 둘 다 메리츠증권 앱과 보유수량이 달라서 사용자가 실제 체결내역을 대조해준 뒤 정정.

04 new1 × meritz — 이번 주의 관계

이번 주 화요일, meritz가 하루 만에 new1과 거의 동등한 기능셋을 갖췄다 — §0(레드와이어/USD 배제, 최초자본 10M→8M) → §1(어제대비 카드·Holdings N/M·SamHynix 폭주버그) → §2(DC/UC/even 캡처) → §3(VIP 3-way) → §4(수수료 모델) → §5(P&L Actions)까지 6단계 포팅 시퀀스가 반나절에 끝났다. 이후 목·금에도 Today's Take, 누적 세금, WATERING 실데이터화, 정합성 자동 체크까지 그대로 따라붙었다 — Analysis 탭이 이제 사실상 new1과 동일한 포맷 이고, meritz만의 차이는 관심종목 스크리너(Fishing/Volume/Foreigner/Link) 부재와 USD 처리뿐이다.

06 Link("연결고리") — 금요일 하루의 4단계

포프(§6-18)의 다음 단계로 금요일 하루 만에 태어나고 세 번 재설계됐다.

① 사전조사 (13:47~14:07)
먼저 "외인이 사면 오른다"는 순진한 가설을 178종목 전체로 쳐봤다 — 상관 거의 0으로 기각. 대신 ±10% 극단값 구간에서만 방향성 있는 패턴을 발견(리포트 06장).
② 기본 구현 (14:30~14:44)
Score = −(ΔF×P)로 다이버전스 후보를 뽑는 패널을 만들었는데, 곧바로 "현재가가 DB 마지막 행이라 Fishing 실시간과 하루 갭이 생긴다"는 버그를 실측으로 잡아 라이브 시세로 교체.
③ 데이터 뿌리 통합 (14:54)
Foreigner의 "평균 대비"와 Link의 "기준일 대비"가 같은 종목을 다른 숫자로 보여주던 문제(와이지-원 사례) — Foreigner 자체를 "기준일pp"로 바꾸고 Link가 그 함수를 그대로 재사용하도록 통합. 이제 두 화면은 항상 같은 숫자를 낸다.
④ 4분면 재설계 + 추세 반영 (15:04~15:33)
"부호 반대=후보"였던 원래 규칙이 태광(+31.6%·외인−3.35%p) 같은 흔한 차익실현까지 최상위로 올리는 걸 발견 → 다이버전스/진행형/이탈/차익실현 4분면으로 분리. 이어서 "누적은 진행형인데 최근 3일은 꺾인" 대한항공식 반전 조짐까지 잡아내는 추세 필드 추가. 배포 크래시 한 번을 거쳐 지금 형태로 정착.

동시에 CFG(Chicken For Golden eggs) — Up/Down·Fishing·Link(4분면×볼륨)를 매일 종합해 상위 3픽을 누적점수로 뽑는 최종 엔진 — 개념이 확정됐다. 지금은 착수하지 않고 (Link가 먼저), 세션이 매일 감시목록 확인 + 매주 금요일 검증 리포트를 쌓아가며 지금의 4분면 가정이 실제로 맞는지 시험하는 단계다.
