## Phase 1 · 2026-08-14~08-18 — 다시 세우기

출발점은 새 프로젝트가 아니라 **"Streamlit 채팅으로 반복 수정하다 꼬여버린 이전
버전"**이었다. 그걸 처음부터 다시 짓는 일로 시작했고, 가장 먼저 만든 건 기능이 아니라
원칙이었다:

- 거래 기록(transactions)이 유일한 진실 공급원 — holdings는 손으로 안 고치고 항상
  재생(replay)해서 파생시킨다.
- 증권사 CSV는 "그날 하루 전체 누적"이지 델타가 아니다 — 실제로 같은 날짜를 append했다가
  네이버 1주가 3주로 뻥튀기된 걸 겪은 뒤 원칙이 됨.
- 메타데이터(종목코드·섹터)는 거래로부터 유추 불가능하니 별도 영구 캐시로 분리.
- 수동 입력 UI는 만들지 않는다 — CSV 업로드가 유일한 데이터 입력 경로.

8/18에 919줄짜리 절차형 스크립트였던 `app.py`를 `constants.py` / `portfolio_core.py` /
`ui_portfolio_tab.py` / `ui_transactions_tab.py`로 분리 — 지금까지 이어지는 파일 구조의
시작.

## Phase 2 · 08-18~09-01 — 기초 다지기

- **transactions 재생 체크포인트** 도입(8/25) — 거래가 몇천 건으로 늘어도 매번 처음부터
  재생하지 않도록. 최근 며칠(safety_days)은 항상 재생, 그 이전은 체크포인트로 확정.
- **"Fishing" 관심종목 스크리너** v1→v2→v3로 세 번 갈아엎음 — 로컬 캐시 파일에 최초가를
  저장하는 방식이 재배포마다 초기화되는 문제를 겪은 뒤, Supabase DB를 최초가 소스로
  바꿔서 구조적으로 해결.
- **자동화 테스트(pytest) 도입**(8/24) — 도입 첫 CI 실행에서 바로 실전 버그를 잡음.
  이후 새 계산 로직을 고칠 때마다 회귀 테스트를 같이 추가하는 관행이 자리잡음.
- **Supabase DB 파이프라인** 구축 — GitHub Actions cron이 매 평일 장마감 후 관심종목
  153개의 시세·거래량·외국인/기관 수급을 긁어 적재. 이후 Volume/Foreigner 스크리너,
  배당 배지, 153종목 밖 보유종목 자동 백필까지 이 파이프라인 위에 얹힘.
- 이 구간에서 실제로 겪은 굵직한 버그 셋: 네이버 실시간 시세 API가 40종목 이상 한
  번에 요청하면 일부만 응답(→20개씩 청크 처리로 해결), cron이 자정 넘겨 지연되면
  거래일 날짜가 하루 밀려 찍힘(→`resolve_trading_date()` 도입), 종목코드 앞자리 0이
  dtype 미지정 시 날아가는 문제.

## Phase 5 · 09-10 — Pit Stop, 그리고 한 달 회고

- **"Pit Stop" 포트폴리오 패널**(9/10 하루) — 매입액이 커지는데 예수금은 평행선을

  지금 형태(⛽ 이모지, Cost Basis/Refill/No Refill/Surplus 4개 선)로 수렴 — 소유자의
  구체적 피드백(스크린샷 첨부 포함)을 매번 반영한 반복 설계 과정의 대표 사례.
  최종적으로는 요약카드 안에 이음매 없이 끼워 넣는 것까지 요구해 관철됨.
  - VIP vs Orchestra 패널도 이날 3-way로 확장되며 "얘기하다 바로 구현하지 말고 스펙
    확정 후 구현하라"는 운영 규칙이 이때 명시적으로 생김.
- **한 달 회고 리포트**(9/10) — "흉터로 쓴 설명서". 당시 기준 315개 커밋, 회귀 테스트

## Phase 6 · 09-11 (오늘) — Link와 CFG, 그리고 이 문서

가장 밀도 높은 하루. 9시간여 만에:

- **누락 체결 보정**(new1: 미스토홀딩스·삼양패키징·크라운해태홀딩스) — 실제 증권사 앱과
  보유수량이 갈렸던 걸 사용자가 실제 체결내역을 대조해 정정.
- **공동보유 43종목 시드·평단가 감사** — meritz가 new1과 겹치는 43종목 전부에서 이기는
  이유를 분해. 시드 크기(상관 −0.12), 물타기 횟수(상관 +0.05)는 무관하고 **평단가
  비율(진입 타이밍) 하나가 상관 −0.994**로 거의 완벽하게 설명한다는 걸 증명(리포트
  "먼저 담은 값을 치르다"). "실력 차이가 아니라 시차"라는 결론.
- **WATERING 상세 그래프 실데이터화** — 종목 상세의 "현재가" 선이 최초매입일→오늘 직선
  이던 걸, 사용자가 "그 사이 꾸준히 내려온 것처럼 보인다"고 지적한 뒤 Supabase 실제
  일별 종가로 교체.
- **"Link"(연결고리) 신설 — 하루 만에 세 번 재설계**:
  1. 사전조사 리포트("조용한 손, 시끄러운 주가") — 관심종목 178개 전체로 외인비중과
     주가의 상관관계를 먼저 검증. 전체 상관은 거의 0으로 기각, 대신 극단적으로 움직인
     구간에서만 방향성 있는 패턴을 발견.
  2. 기본 구현 — 사용자가 지정한 조건("가격 빠지는데 외인은 담는 것만 잡아라, 전체
     상관관계를 보려는 게 아니다")대로 다이버전스 후보 스크리너 제작.
  3. 실측 버그 두 건을 그 자리에서 수정 — 현재가가 DB 마지막 행(장중엔 하루 뒤처짐)이라
     Fishing 실시간 값과 어긋남, Foreigner와 Link가 외인비중 계산에 서로 다른 기준(전체
     평균 대비 vs 기준일 대비)을 써서 같은 종목이 화면마다 반대로 보임 — 후자는 Foreigner
     쪽 계산 자체를 바꿔서 두 화면이 항상 같은 함수를 쓰게 만드는 구조적 해법으로 처리.
  4. 4분면 재설계 — 사용자가 "많이 올랐다가 외인이 판 것"(차익실현)과 "많이 빠졌는데
     외인이 담은 것"(다이버전스)이 첫 버전에서 똑같이 취급되는 걸 실제 후보 목록(태광·
     성광벤드)을 보고 지적, 다이버전스/진행형/이탈/차익실현 4분면으로 재설계.
  5. 추세 반영 — "누적으로는 진행형인데 최근 3일은 꺾인" 대한항공 사례를 사용자가 직접
     짚어서, 누적값만이 아니라 최근 3거래일 추세까지 보는 로직 추가.
  6. 배포 크래시 한 번(함수 인자 순서 실수)을 실측으로 발견해 즉시 수정.
- **CFG(Chicken For Golden eggs) 개념 확정** — Link를 포함해 Up/Down·Fishing까지
  종합해서 매일 상위 3픽을 누적 점수로 추리는 최종 판단 엔진의 개념 설계. 아직 코드는
  없음 — "Link가 먼저 안정화된 뒤" 착수하기로 명시적으로 순서를 정함.
- **주간 리포트**("같은 뿌리, 다른 가지") — 이번 주(9/7~9/11) 137개 커밋, 재발 버그
